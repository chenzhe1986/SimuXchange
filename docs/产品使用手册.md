# SimuXchange 产品使用手册

> SimuXchange 是一款**模拟交易所交易网关（TGW）**的测试工具：
> 它假扮真实的交易所网关，接受您的柜台系统（OMS）按交易所 Binary 协议发来的
> TCP 连接和委托，并按您配置的策略回送确认回报、成交回报或拒单——
> 让柜台系统不必连接真实交易所就能完成联调测试。
>
> 支持三类网关（新建网关时选择分类）：**深圳统一网关**（深交所 Binary 协议）、
> **上海竞价网关**（上交所竞价平台 Binary 0.54 协议）与**上海新债券网关**（上交所债券平台 Binary 1.90 协议）。
>
> 本软件**没有真实订单簿与撮合**，所有回报均为按策略模拟生成。

## 1. 安装与启动

### 1.1 单机模式

把发布压缩包解压后（文件夹里是 `simuxchange.exe` 与 `Linux\` 等子目录），
将 `simuxchange.exe` 与 `simx.config.json`（可选，缺省自动生成）放同一目录，
双击 exe 启动即可，无需安装。

发布目录里自带 **Linux 后端**（`Linux\simx-server`，musl 静态编译），
可拷到 Linux 服务器做远程部署（见 1.2 节），无需另找安装文件。

首次启动后，程序会在 exe 同目录自动生成 `gateways.json` 保存您的网关配置，
下次启动自动恢复。

### 1.2 远程模式（引擎部署在服务器上）

适合场景：模拟网关跑在测试服务器/Linux 上，本机只做操作界面。

1. 在服务器上运行独立后端（推荐用 crontab 定时启停，早 8 点开晚 10 点关，
   见《构建调试手册》6 节）：
   ```
   ~/simx-server/simx-server --listen 0.0.0.0:9800
   ```
   加 `--auto-start` 参数后，后端启动完成会**自动恢复上次运行中**的网关（引擎把
   网关启停状态记在 `gateways.json` 的 `wasRunning` 字段，只启动上次退出时仍在运行的网关），
   无需再打开界面手动启动（适合定时启停的无人值守场景）；不带该参数则所有网关都不
   会自动启动：
   ```
   ~/simx-server/simx-server --listen 0.0.0.0:9800 --auto-start
   ```
2. 启动桌面端，点击右上角**状态徽章**（原来只显示“本地引擎/远程后端”的地方），
   在「后端连接设置」弹窗里可**添加多个远程后端**：只需填**服务器地址**
   （IP 或域名，如 `192.168.1.10`；地址里带端口如 `192.168.1.10:9810` 也可），
   **端口**默认 9800，系统自动补 `ws://` 前缀与 `/ws` 路径并实时预览完整地址，
   **名称可选**（留空自动按地址生成），添加后自动切换过去；以后点列表项即可随时切换。
   保存后立即生效，并写入程序目录的 `simx.config.json`（下次启动自动生效）；
   想回到单机模式，点列表里的「本地引擎」即可，全程无需改文件。
3. 徽章显示「<名称>·已连接」即成功。

远程模式下，引擎运行在服务器上：网关配置保存在服务器的 `gateways.json`，
报文文件写在服务器的 `packets/` 目录；界面仅作遥控台，所有操作
（启停、新建网关、改配置、看统计、看报文）都通过网络实时执行。

断线后界面会**每 2 秒自动重连**，服务恢复后无需手动操作。
若启动时已处于远程模式但连不上服务器，徽章显示「<名称>·连接中…」，
此时仍可点击徽章切回本地引擎。

| 主区 | 选中网关的操作按钮和平台卡片网格 |
| 底部 | 运行日志面板，可折叠、按级别过滤 |

**概念说明**：一个**网关**是一组平台的集合，整体启动/停止；
一个**平台** = 一个 TCP 监听端口，柜台连接的就是平台的端口。
可以建多个网关模拟多套环境，互不干扰。

**网关分类**：新建网关时需选择分类，决定该网关下所有平台说哪套协议：

| 网关分类 | 协议 | 平台类型 |
| --- | --- | --- |
| 深圳统一网关 | 深交所 Binary | 6 种平台（现货集中竞价等） |
| 上海竞价网关 | 上交所竞价平台 Binary 0.54 | 竞价平台（PlatformID=0） |
| 上海新债券网关 | 上交所债券平台 Binary 1.90 | 新债券平台（PlatformID=2） |

分类**创建后不可修改**（重命名时分类下拉框为只读）；需改分类请新建网关。

**网关目录**：网关可归入**目录**（文件夹）分组展示，目录最多嵌套两层
（根级目录内可再建子目录）。目录数据存在后端，所有用户看到的目录一致；
目录的折叠状态存在本机（无记录时默认全部展开）。操作见 5.6 节。

**网关标签与时间**：每个网关可打**标签**（如"仿真""验收"，界面以色块展示，
存储时用逗号分隔）与写**备注**，存在后端；侧栏顶部可按标签筛选网关。
网关与平台均有后端维护的**创建时间 / 修改时间**，右键「详情」弹窗查看
（网关的标签/备注在详情弹窗里编辑）。详见 5.7 节。

## 3. 快速上手（四步开始联调）

1. **新建网关**：左侧栏点「＋ 新建」，输入名称、选择**网关分类**（深圳统一网关 /
   上海竞价网关 / 上海新债券网关）后保存。分类决定该网关用哪套协议，创建后不可改。
2. **添加平台**：主区点「＋ 添加平台」，至少确认两项——
   **监听端口**（柜台要连的端口，自动预填空闲端口）和**报单自动回报模式**
   （默认"全部成交"），其余保持默认即可，点「保存」。
3. **启动网关**：点「▶ 启动网关」。平台卡片显示绿点「监听中」即就绪。
4. **柜台接入**：让柜台系统连接 `本机IP:平台端口`，完成 Logon 后即可发送委托，
   界面实时显示连接、统计和日志。

> ⚠️ 网关**运行中**：**模拟回报策略与回报延迟**可直接修改，保存后**实时生效**
> （无需停止网关，见 4.3/4.4）；但**不允许添加/删除平台或删除网关**
> （避免端口状态错乱），相关按钮会置灰；其余平台配置（端口、密码等）
> 需停止网关后修改。

## 4. 平台配置详解

在平台编辑弹窗中可配置：

### 4.1 基础信息

| 配置项 | 说明 |
| --- | --- |
| 平台名称 | 仅用于界面显示 |
| 平台类型 (PlatformID) | **选项随网关分类变化**：深圳统一网关为 1=现货集中竞价、2=综合金融服务、3=非交易处理、4=衍生品集中竞价、5=国际市场互联、6=固定收益；上海竞价网关仅 0=竞价平台；上海新债券网关仅 2=新债券平台 |
| 监听地址 | `0.0.0.0`=所有网卡均可接入；`127.0.0.1`=仅本机 |
| 监听端口 | 柜台连接的 TCP 端口，多个平台不能重复 |
| 网关 CompID | 回报中的 SenderCompID（网关的机构代码） |
| 平台分区号 (PartitionNo) | **支持多个**（逗号分隔，如 `115,116,117,118`）：回报按**证券代码哈希**分配到其中一个分区（同一证券恒落同一分区，保证该证券的确认/成交/撤单回报都在同一分区）；留空则按单分区处理。（上交所回报为 SetID） |
| 校验登录密码 | 勾选后，柜台 Logon 中的 Password 必须与此处一致，否则拒绝登录（**上海竞价/新债券网关登录无密码字段，故无此选项**） |
| 展示收发报文 | **默认勾选**。勾选后，平台卡片出现「报文」按钮，点击弹出窗口实时查看该平台全部连接的收发报文（按交易所字段名解析 + 收发颜色区分，见 4.2）；同时**自动持久化**到数据目录 `packets/` 下的日志文件，无需单独设置 |
| 缓存订单 | **默认开启**。开启后，平台收到的所有委托（及其后续回报）会被缓存下来，可通过平台卡片上的「订单」按钮随时查看全部订单及其实时状态（见 4.5）；关闭后不缓存、卡片不显示「订单」按钮 |

> ⚠️ **单连接限制**：每个平台同一时刻只接受**一个柜台连接**。已有连接时，新连接会被直接拒绝
> （柜台侧表现为连接建立后立即被断开）；原连接断开后可随时重新接入。

### 4.2 报文捕获（展示收发报文 + 字段解析 + 自动持久化）

「展示收发报文」为**单一开关（默认勾选）**：勾选后同时开启界面展示、按交易所字段名解析、持久化到文件三件事，无需分别设置。

| 效果 | 说明 |
| --- | --- |
| **界面展示** | 平台卡片连接概览行出现「报文」按钮，点击弹出**收发报文窗口**：该平台**所有历史连接**收发的报文按接入时间顺序展示，**每个连接的报文独占一段**，段首是明显的分组标题（如 `连接 #1 · 127.0.0.1:52300 · 20:35:26 接入 · 在线/已断开 · N 条`），段与段之间以虚线分隔，新报文自动滚动到底部。窗口默认大小与订单弹窗一致，同样支持**右下角拖动调整大小**与 ⛶ **最大化 / 还原** |
| **字段解析** | 每条报文在原始字节下方按**交易所字段名**逐字段解析展示（如深交所报文的 `MsgType`、`ClOrdID`、`SecurityID`、`Side`、`Price`、`OrderQty` 等）。解析字段与原始报文用**不同字体**区分层次；**绿色=收到的报文，琥珀色=发送的报文**，一眼分清方向 |
| **持久化** | 报文在记录内存的同时逐行追加写入数据目录 `packets/` 下的日志文件，**文件内容与弹窗展示一致**（原始报文行下方即解析字段缩进行），连接断开后文件保留，可随时用任意文本编辑器打开查看 |

每条报文的展示格式（弹窗与文件相同）：

```
20:35:26.583 RECV  FE 3F 86 0C 18 00 00 00 ...   ← 原始报文（大写十六进制字节）
                   MsgType                 : 100101 (现货新订单)
                   ClOrdID                 : OMS000123
                   SecurityID              : 000001
                   Side                    : 1 (买)
                   Price                   : 10.0100
                   OrderQty                : 100
```

> 解析失败或未知消息类型时只展示原始报文行；报文文件**按日期 → 网关名_平台名分层存放**，一眼定位某天某平台某连接的报文：

```
packets/
└── 20260814/                      ← 按日期分文件夹（YYYYMMDD）
    └── 分组7深圳模拟撮合1_现货集中竞价交易平台/   ← 日期下按“网关名_平台名”分文件夹
        └── pkg_203526_ip-192_168_1_100_port-8080.log   ← 每条连接一个文件
```

文件名格式：`pkg_<接入时分秒>_ip-<客户端IP点转下划线>_port-<客户端端口>.log`（如
`pkg_203526_ip-192_168_1_100_port-8080.log` = 20:35:26 接入的 192.168.1.100:8080 柜台）。

> 提示：即使中途关闭报文弹窗，报文仍会持续写入文件；历史连接断开后其文件保留，随时可回看。

### 4.3 报单自动回报模式

未成交的挂单可以在订单界面手动发送回报。

界面为**两级选择**：一级下拉选大类（固定回报模式 / Lua 脚本配置 / 回放行情撮合 /
关闭自动回报），选“固定回报模式”后右侧出现具体的子模式下拉。

| 大类 | 收到委托后的行为 |
| --- | --- |
| 固定回报模式 | 右侧子模式下拉 6 选 1，见下表 |
| Lua 脚本配置 | 执行您编写的 Lua 脚本，按脚本返回值生成任意组合的确认/成交/拒单回报，详见 [Lua脚本回报编写说明.md](Lua脚本回报编写说明.md) |
| 回放行情撮合（待开发） | 暂未开发行情回放撮合：当前行为与「关闭自动回报」一致（委托只进订单缓存、不自动回任何回报，由订单弹窗手动回复），后续开发敬请期待 |
| 关闭自动回报 | 不自动回任何回报：委托只登记进订单缓存（订单界面可见），由您在订单弹窗里手动回复确认/成交/拒单/撤单 |

固定回报模式的子模式（收到委托后的行为）：

| 子模式 | 行为 |
| --- | --- |
| 全部成交 | 1 条确认 + 1 条全量成交（成交价=委托价） |
| 部分成交 | 1 条确认 + 1 条随机数量的部分成交（剩余量保持挂单状态） |
| 全部成交（随机拆多笔） | 1 条确认 + N 条成交，数量随机拆分；价格按档位逐笔变化——买单从委托价逐档递减、卖单逐档递增（模拟“先吃掉便宜的对手盘”） |
| 部分成交（随机拆多笔） | 1 条确认 + N 条部分成交 |
| 只回确认回报 | 只回 1 条确认，不产生成交 |
| 自动拒单 | 回执行报告拒绝（200102, ExecType=8）或业务拒单独消息（MsgType=4），二选一；原因码和说明文字可配置 |

> 选「自动拒单」时，模式参数区最底部**只显示「确认回报延迟」**——拒单回报也按这个
> 延迟参数发出（自动拒单没有确认/成交回报，故不显示「成交回报延迟」；「只回确认」同理）。

> **策略支持热更新**：网关**运行中**修改策略或回报延迟，保存后对**后续委托实时生效**，无需停止网关（其余平台配置如端口、密码等仍需停止后修改）。

拆单模式的附加参数：
- **拆单笔数**：在最小~最大之间随机（如 3~5 表示每笔委托拆成 3 到 5 笔成交）
- **价格档位**：每笔成交相对上一笔的价格变动（元）

Lua 脚本模式的附加说明：
- 只有一个带语法高亮的输入框（原“Lua 回报脚本”与“AI 生成脚本输入框”已合并），
  默认放一段需求示例文本——点「AI 生成脚本」后，AI 会把框内内容（示例或您改写的
  描述）变成真正的 Lua 脚本并留在同一框内（您的原话自动转为脚本头部注释）；
- 点「AI 生成脚本」前会先做语法校验：框内**已经是合法 Lua 脚本**时（粘贴的
  或上次生成的结果），直接提示“已是合法 Lua 脚本，无需再生成”，**不会调大模型**；
  只有输入需求描述文字才会调用（默认示例文本是中文描述、不是合法脚本，首次生成不受影响）；
- 框内内容就是 AI 生成的需求描述，改什么逻辑直接改字再点「AI 生成脚本」即可；
  不经过生成、直接粘贴已有脚本也能用；
- AI 发现需求逻辑**自相矛盾**时不会生成脚本，会逐条指出矛盾点供您修正；
  发现需求用到脚本手册**不支持的功能**（如撤单控制、取实时行情）时，会逐条列出
  不支持的点；
- 保存时若框内仍是默认示例提示词会被拦截，提示先点「AI 生成脚本」或写好脚本再保存；
- 「脚本手册」：弹出程序内置的《Lua 脚本回报编写说明》全文（随程序打包，
  Markdown 渲染，无需另行打开文档文件）；
- 「检查脚本」按钮可即时校验语法（不保存）；保存时后端也会强制校验，
  语法错误会弹窗提示行号与原因，编辑弹窗保持打开可直接修改，可继续手动调整；
- 脚本运行在沙箱中（无文件/系统访问），运行时出错则该笔委托不自动回报并记录日志；
- 撤单回报不受脚本控制，仍按 4.3.1 的撤单模式配置执行；
- Lua 模式下**确认/成交延迟只能由脚本各项的 `delayMs` 控制**：界面不显示确认/成交延迟
  输入框，保存时自动归零；未写 `delayMs` 的项同步（0 延迟）发出。撤单延迟仍按 4.4 配置生效。

### 4.3.1 撤单自动回报模式

| 模式 | 收到柜台撤单请求后的行为 |
| --- | --- |
| 默认（存在挂单时自动撤单成功，否则撤单拒单） | 原单在途（已报/部分成交）→ **撤单成功**（执行报告 ExecType=4）；找不到原单或原单已是终态 → **撤单拒单** |
| 全部撤单成功 | 无论原单在途/终态/找不到，一律回**撤单成功**（执行报告 ExecType=4） |
| 全部撤单拒绝 | 无论原单状态一律回**撤单拒单**，原因码可配置 |

**前台拒单**（勾选）：撤单拒单改发**业务拒绝消息**（深交所 MsgType=4 / 上交所 204），
不进执行报告流；原因码回填到业务拒绝消息的原因字段（未勾选时回填到撤单拒单消息的原因字段）。

**撤单回报延迟**（毫秒）配置在本区块底部（规则见 4.4），任何报单模式都可设置，
对撤单成功与撤单拒单回报均生效。

### 4.4 回报延迟

回报延迟配置已拆分到两个模式区块下：

- **确认回报延迟 / 成交回报延迟**：在「报单自动回报模式」区块内、仅在**固定回报模式**
  下显示，分两列展示，分别对应确认回报与成交回报的“最小 ~ 最大”毫秒数；位置随模式
  而定——「随机拆多笔」两种模式位于拆单笔数、价格档位**下方一行**，其余固定模式紧跟
  模式选择行，自动拒单在参数区最底部只显示「确认回报延迟」（拒单回报也按该配置）；
- **撤单回报延迟**：在「撤单自动回报模式」区块内显示（撤单成功与撤单拒单回报均适用），
  任何报单模式都可配置（撤单不受 Lua 脚本接管）。

延迟规则如下：

| 设置 | 效果 |
| --- | --- |
| 最小 = 最大 = 0 | 同步回报（收到委托立即回，顺序严格） |
| 最小 = 最大 > 0 | 固定延迟 |
| 最小 < 最大 | 每笔在区间内随机延迟（更接近真实网络） |

拆单时每笔成交单独抽样延迟。只回确认回报与自动拒单模式没有成交回报，不显示
「成交回报延迟」输入框。

> **Lua 脚本模式的例外**：确认/成交延迟不受本配置控制（Lua 模式下不显示这两个
> 输入框），延迟只能由脚本各项的 `delayMs` 指定，未写 `delayMs` 的项
> 同步发出；撤单延迟照常按上表配置生效（脚本不接管撤单）。

### 4.4.1 ETF 申赎成份股明细（深圳非交易处理平台专用）

深圳**非交易处理平台**（平台类型 3）的编辑弹窗在「成交回报延迟」下一行有配置项
「**ETF清单文件路径**」（? 图标说明：ETF申赎需要从该目录读取清单文件并发送成交明细；
其他平台类型不显示该项）：

- **用途**：ETF 实时申购赎回委托（101201）的执行报告（201202）需要携带**成份股明细**
  （不足成份券、每只成份券的交付数量与现金替代金额），而柜台委托报文里不含这些数据。
  填写该目录后，网关收到 ETF 申赎委托时按**证券代码**从目录中查找**日期最新**的
  清单文件（文件名格式 `pcf_<代码>_<YYYYMMDD>.xml`，如 `pcf_159920_20260615.xml`
  表示代码 159920 在 2026-06-15 的清单，文件格式遵循交易所 PCF 文件定义），解析后
  把全部成份股明细填入执行报告；
- **计算规则**：篮子数 = 委托份额 ÷ 清单中的最小申赎单位（CreationRedemptionUnit）；
  每只成份券交付数量 = 每篮子数量（ComponentShare）× 篮子数；现金替代金额按委托方向取
  申购替代（CreationCashSubstitute）或赎回替代（RedemptionCashSubstitute）× 篮子数；
- **目录路径**：前后端分开部署时，该目录一般位于 **simx-server 所在的 Linux 服务器**上
  （填服务器的本地路径，如 `/opt/simx/pcf`）；一个目录下可存放所有 ETF 代码、多日期的
  清单文件，网关自动按代码 + 最新日期选取；
- **目录很大也不影响性能**：清单的查找与解析带缓存——目录内容变化（新增或更新清单
  文件）后下一笔委托即时生效；目录无变化时不会重复遍历目录、重复解析文件；
- **留空 / 找不到文件**：留空 = 不启用（执行报告成份股数为 0，与旧行为一致）；
  目录不可用、或目录中没有该代码的清单文件时，同样按 0 只成份股回复，并在日志面板
  推送告警信息（便于发现路径配置错误或清单缺失）；
- **热更新**：该配置随策略配置保存，网关**运行中**修改立即生效（与回报策略热更新一致）；
- **报文查看**：报文弹窗对执行报告中的成份股重复组按
  `Security[i].UnderlyingSecurityID / SecurityIDSource / DeliveryQty / SubstCash`
  结构化展示全部成份股明细，与原始字节同屏对照。

> 参考资料：清单文件的内容定义（交易所参考表格）与两只 ETF 的真实示例清单
> （`pcf_159901_20260615.xml`、`pcf_159920_20260615.xml`）存放在 `docs/PCF示例/`。

### 4.5 订单缓存与撤单回复

「缓存订单」默认开启：平台收到的每笔委托都会登记一条记录，后续确认/成交/拒单/撤单回报会实时更新其状态，数据保存在内存中（重启后清空）。

- **查看订单**：平台卡片上出现「订单」按钮（开启缓存后才有），点击弹出订单列表弹窗，展示每笔委托的**时间、委托编号、交易所订单号、证券、方向、价格、委托量、成交量、剩余量、状态**；列表每 1 秒自动刷新；
- **窗口大小**：弹窗默认较大，可用**右下角拖把手自由调整大小**，头部 ⛶ 按钮**最大化 / 还原**（还原回到之前拖好的大小）；表格列宽随窗口宽度**等比例伸缩**，窗口多宽表格就多宽，右侧不留空白，最小宽度保证全部列完整展示、无需左右滚动；
- **只显示在途订单**：弹窗右上角勾选后，列表只保留**已报 / 部分成交**的在途订单（全成/已拒/已撤为终态订单，被隐藏）；
- **状态含义**：已报（new）= 已确认未成交；部分成交（partial）= 成交了一部分、剩余仍挂单；全部成交（filled）、已撤（cancelled）、已拒绝（rejected）为终态。

**撤单回复规则**（撤单自动回报模式为「默认」时）：收到柜台撤单请求后，按原订单当前状态回复——

| 原订单状态 | 撤单结果 | 回报 |
| --- | --- | --- |
| 在途（已报 / 部分成交） | **撤单成功** | 执行报告 ExecType=4（已撤），订单状态变为「已撤」 |
| 终态（全部成交 / 已拒绝 / 已撤） | **撤单失败** | 撤单失败消息（深交所 290008 / 上交所 59） |

配置「回撤单拒单」或勾选「前台拒单」时的行为见 4.3.1。

**手动回复在途订单**：订单列表弹窗中，**已报 / 部分成交**的在途订单行末有「回复」按钮，点击在行下方展开手动回复面板，可主动向柜台补发四种回报（默认四块**并排一行**均分宽度；窗口收窄后自动切成**两行两列**，每行两块均分）：

| 回报 | 可配置项 | 默认值 | 说明 |
| --- | --- | --- | --- |
| **确认回报** | 无 | — | 执行报告 ExecType=0（已报）；订单保持「已报」状态、可继续回复成交/拒单/撤单（适合「不自动回复」模式：委托挂起后先回确认） |
| **成交回报** | 成交数量、成交价格 | 剩余量（全成）、委托价 | 按自然单位填写（股/元）；数量超过剩余量时按剩余量全成；剩余量不足 1 股时提示无法成交（不能构造合法成交回报） |
| **拒单回报** | 拒单原因代码、**前台拒单开关** | 原因 1、不勾选 | 默认以执行报告（ExecType=8）形式发出；勾选「前台拒单」后改发**业务拒绝消息**（深交所 MsgType=4 / 上交所 204），不进执行报告流 |
| **撤单成功回报** | 无 | — | 剩余量全部撤掉，执行报告 ExecType=4 |

> 成交/拒单/撤单发送后订单进入终态，不能再回复；确认回报可重复发送。
> 手动回报统一发往**当前活动连接**（历史连接发来的订单同样走当前连接）；手动确认/成交/拒单会计入平台统计（确认/成交/拒单），手动撤单成功不计入「撤单」计数（那是撤单请求的计数）。

### 4.6 前端操作日志

前端（本地桌面端或远程 WebSocket 客户端）的每个操作都会追加写入数据目录 `log/` 下的
日志文件（与报文文件 `packets/` 一样**按日期归档**）：

```text
log/
└── 20260816/                ← 按日期分文件夹（YYYYMMDD）
    └── ops.log              ← 当天全部操作日志
```

每行格式为 `时间  前端IP  操作`，例如：

```text
2026-08-16 10:00:00.123  192.168.0.1  新建网关 测试网关（1 个平台）
2026-08-16 10:00:05.456  192.168.0.1  启动网关 测试网关
2026-08-16 10:12:30.789  192.168.0.1  手动回复订单 A0001（成交）：网关 测试网关 平台 现货竞价
```

- 记录范围：**前端接入/断开**（远程模式按 WebSocket 对端 IP 记录，本地桌面端固定 `127.0.0.1`）
  以及全部操作（新建/保存/删除/启动/停止网关、热更新策略、重置统计、手动回复订单）；
- 每秒轮询的只读命令（快照、报文列表、订单列表）不记，避免刷屏；
- 远程模式由 simx-server 记录真实对端 IP，方便追溯是哪台机器在操作。

### 5.5 版本信息与自动升级

**查看版本**：点击顶栏右侧的 **ⓘ 关于**按钮（有待应用更新时它会变成红色
「↻ 重启以更新」，详见下文「客户端升级流程」），弹窗显示当前版本号（如 1.3.0）与
更新说明。弹窗底部有 **GitHub / Gitee** 开源主页
链接（本项目遵循 GPL 开源协议），点击后在系统默认浏览器中打开项目主页。

**配置更新服务器**：点击右上角状态徽章（本地引擎/远程后端），在「后端连接设置」
弹窗里填「更新服务器地址」（如 `http://192.168.1.10:8080`，留空则不检查更新），
保存后立即生效并写入 `simx.config.json`。

**自动检查**：程序启动 3 秒后自动向更新服务器拉取 `version.json`；服务器版本号
比当前大时弹窗提示。检查失败（服务器没开、地址填错等）**静默忽略**，不影响正常
使用。

升级采用**目录发布**：服务器上只放"整个程序目录 + 一个版本号文件"，客户端把整个
目录下载下来原地覆盖，不需要安装包。

#### 服务器端发布新版

把**压缩包解压后的整个程序目录**（simuxchange.exe 与其它文件/子目录）拷到更新
服务器目录，再放一个版本号文件（二选一，数字点分比较，如 1.3.0 > 1.2.9）：

- `release.txt`：纯文本，内容仅一行版本号，如 `1.3.0`；
- `release.json`：`{"version": "1.3.0"}`。

服务器自动扫描目录生成 `version.json` 文件清单（含子目录、大小、sha256 校验值），
并对全部文件（版本号文件和清单本身除外）提供下载，用户不用写任何清单。

- 用项目自带的 **`simx-update-server`**（推荐，见《构建调试手册》6.6 节）时以上
  全部自动完成，浏览器打开管理页可查看当前清单（版本号 + 发布文件数）；
- 用任意 HTTP 静态目录代替时，需按下面格式手动写一份 `version.json`（发布文件
  都要列在 files 里与目录实际一致）：

```json
{
    "version": "1.3.0",
    "files": [
        { "name": "simuxchange.exe", "size": 52000000, "sha256": "…" },
        { "name": "resources/data.bin", "size": 1000, "sha256": "…" }
    ]
}
```

#### 客户端升级流程

发现新版本后点「下载更新」，把整个目录的全部文件下载到本机临时区
（**先下载其它文件、最后下载 simuxchange.exe**，逐个文件校验完整性）。下载完
成后，顶栏右侧的「ⓘ 关于」按钮变成**红色脉冲的「↻ 重启以更新」**：

- **点红色按钮**：自动退出 → 用下载的新文件覆盖程序目录（其它文件先覆盖、
  最后覆盖 exe）→ 自动重新启动，即为新版本；
- **不点直接关闭程序**：退出时自动完成覆盖，**下次启动即为新版本**；
- 只覆盖发布清单列出的文件，程序目录里的配置/网关数据（`simx.config.json`、
  `gateways.json` 等）不受影响；
- 更新中途断电等情况：老版本程序文件不受影响，下次启动仍可正常使用，
  重新点一遍按钮/关闭即可重试。

**远程后端的自检**：服务器上启动 simx-server 时加
`--update-url http://<服务器IP>:8080`，启动日志会打印"发现新版本 / 已是最新
版本"提示（只提示不自动替换，请按提示手动部署新版）。

### 5.6 网关目录与侧栏宽度

**目录分组**：网关多时可按目录归组，目录最多嵌套两层（子目录内不能再建目录）：

- **新建目录**：侧栏空白处右键「＋ 新建目录」；
- **新建子目录**：在根级目录行上右键「＋ 新建子目录」（子目录内不能再建）；
- **网关移入目录**：把网关行**拖拽**到目录行上松手即可；或在网关右键菜单选
  「移动到目录…」，在弹窗里点选目标位置（点「根层级」可移出目录）；
- **折叠/展开**：点击目录行即折叠或展开，折叠状态保存在本机、下次启动保持；
  换电脑或清缓存后恢复默认全展开（目录数据存在后端，所有用户看到的目录一致）；
- **删除目录**：目录行右键「删除目录」，弹窗里可勾选「同时删除目录下的网关」：
  - 勾选：目录、子目录与其下全部网关一并删除；若有网关在运行，删除会失败并
    提示「XXX 网关是运行状态，不允许删除」（先停止该网关再删）；
  - 不勾选：仅删除目录，里面的网关自动移至根层级（网关配置不丢）。

**侧栏宽度**：侧栏与主区之间的分界线可按住左右拖动调整宽度（160~480 像素），
宽度自动保存在本机，下次启动保持。

### 5.7 网关标签、备注与时间（详情弹窗）

**创建时间 / 修改时间**：网关与平台自创建起由系统自动记录两个时间（存在后端，
格式 `YYYY-MM-DD HH:MM:SS`）：
- **创建时间**：网关/平台新建时生成，之后不变（重命名、改配置都不影响）；
- **修改时间**：每次配置发生变化时刷新。纯粹启动/停止网关只算运行状态、
  不算配置修改，不刷新修改时间；
- 老版本升级过来的配置没有时间记录，首次启动时会自动按当前时间补齐。

**查看与编辑**：
- **网关详情**：侧栏网关项右键 →「查看详情/标签/备注」，弹窗里显示名称、
  分类、所属目录、运行状态与创建/修改时间，下方可编辑**标签**与**备注**，
  点「保存」生效（网关运行中也可以保存——只改配置不动运行状态）；
- **平台详情**：平台卡片右键 →「详情」，只读展示所属网关、监听地址与
  创建/修改时间。

**标签筛选**：侧栏顶部有一排标签 chip——「全部 / 无标签 / 各标签」，
点选后侧栏只显示带该标签的网关（目录按可见网关数显示，一个都没有的目录
整棵隐藏）。每个标签有固定专属颜色（按标签名自动分配，同名恒同色），
筛选 chip、侧栏网关行与详情弹窗里的标签全部以**色块**展示，多标签一眼
可分。筛选只是展示层过滤，不修改任何配置。

**标签的添加与移除**：详情弹窗里点「＋ 添加标签」，下拉面板会列出
当前所有网关已用到的标签，**点一下某个标签即添加**；也可以在输入框里
直接输入新标签名回车**新建**。已添加的标签以色块显示在下方，**再点它
一下就移除**。色块颜色由标签名自动生成、不单独存储——因此某个标签
在最后一个网关上移除后，它的所有信息也随之消失，不残留任何数据。

## 6. 柜台对接说明（给对接方的技术参考）

柜台系统按对应交易所的 **Binary 协议**（均大端序）连接平台端口。以下按网关分类分别说明。

### 6.1 深圳统一网关（深交所 Binary）

#### 会话流程

```
柜台                          SimuXchange
 │ ── Logon(1) ──────────────────▶ │   校验密码（若开启）
 │ ◀────────────── Logon(1) ────── │   双方 CompID 对调
 │ ◀────────────── 平台信息(9) ──── │
 │ ◀────────────── 平台状态(6) ──── │
 │ ── 回报同步(5) ────────────────▶ │   可选：断线重连/重收当天回报时发送
 │ ◀─── 按 begin 重发历史回报 ───── │   仅当开启“展示收发报文”（有捕获缓存）；
 │                                   │   发完不回任何结束标记
 │ ⇄  Heartbeat(3) 按 Logon 协商的间隔互发
 │ ── 新订单 100101 ──────────────▶ │
 │ ◀────── 确认 200102 / 成交 200115 / 拒单 ── │   按平台策略
 │ ── 撤单 190007 ────────────────▶ │
 │ ◀─ 执行报告 200102(ExecType=4) ─ │   在途订单 → 撤单成功
 │ ◀────────── 撤单失败 290008 ──── │   终态订单 → 撤单失败（需开启缓存订单）
```

**回报同步（5.2）说明**：OMS 在回报同步消息中按分区指定“期望接收的下一条回报记录号”
（ReportIndex，每个分区从 1 开始连续编号），网关从该记录号开始重发本分区已发出的
全部回报（**保留原记录号**，含历史连接发过的，跨分区互不串扰）。按实测真实交易所
行为，网关**发完历史回报后不回“回报结束”等任何结束标记**，柜台按回报记录号自行
对账。未开启「展示收发报文」时没有捕获缓存，不重发任何历史回报；含非法/重复分区号
的同步请求整条丢弃，回 20106 业务拒绝。

#### 编码要点

| 项 | 规则 |
| --- | --- |
| 报文结构 | MsgType(4) + BodyLength(4) + Body + Checksum(4)，均大端序 |
| 定长字符串 | 右补空格 |
| 价格 Price N13(4) | 实际价格 × 10000（12.34 元 → 123400） |
| 数量 Qty N15(2) | 实际股数 × 100（500 股 → 50000） |
| 心跳超时 | 超过心跳间隔 3 倍未收到任何报文，连接被断开 |
| 回报记录号 ReportIndex | 每个分区从 1 开始**连续编号**（不跨分区共用序号），由网关发送时分配 |

#### 支持的消息类型

- 会话层：Logon(1)、Logout(2)、Heartbeat(3)、平台状态(6)、平台信息(9)、回报同步(5)
- 业务层：新订单 100101、确认回报 200102、成交回报 200115、
  业务拒绝(4)、撤单 190007 → 撤单成功 200102(ExecType=4) / 撤单失败 290008（按原单状态，见 4.5）
- ETF 实时申购赎回：新订单 101201 → 执行报告 201202（成份股明细按「ETF清单文件路径」
  配置的清单文件回复，见 4.4.1；该业务无成交回报）

### 6.2 上海竞价网关（上交所竞价平台 Binary 0.54）

#### 会话流程

```
柜台                          SimuXchange
 │ ── Logon(40) ─────────────────▶ │   无密码字段
 │ ◀───────────── Logon(40) ────── │   双方 CompID 对调
 │ ◀───────────── 平台状态(209) ─── │
 │ ◀──────────── 执行报告信息(208) ─ │
 │ ── 分区序号同步 206 ────────────▶ │   登录后必须先做
 │ ◀──────── 序号同步响应 207 ────── │   207 后按 begin 重发历史回报
 │                                   │   （有捕获缓存时，保留原记录号）
 │ ⇄  Heartbeat(33) 间隔 5~60 秒互发
 │ ── 新订单 58 ──────────────────▶ │
 │ ◀──── 申报响应 32 / 成交 103 / 拒单 204 ── │   按平台策略
 │ ── 撤单 61 ────────────────────▶ │
 │ ◀──────── 执行报告 32(ExecType=4) ── │   在途订单 → 撤单成功
 │ ◀────────── 撤单失败 59 ──────── │   终态订单 → 撤单失败（需开启缓存订单）
```

#### 编码要点

| 项 | 规则 |
| --- | --- |
| 报文结构 | MsgType(4) + MsgSeqNum(8) + MsgBodyLen(4)（16 字节头）+ Body + Checksum(4)，均大端序 |
| 校验和 | 报文所有字节按 uint8 累加（自然溢出取低 8 位） |
| 消息序号 | MsgSeqNum 由网关发送时递增赋值 |
| 价格 Price N13(5) | 实际价格 × 100000（12.34 元 → 1234000） |
| 数量 Qty N15(3) | 实际股数 × 1000（500 股 → 500000） |
| 登录门槛 | 登录后需先完成分区序号同步（206→207），同步前的执行报告会缓存、同步后补发；同步响应(207)后按各分区 BeginReportIndex 重发历史回报（有捕获缓存时） |
| 心跳 | HeartBtInt 协商区间 5~60 秒 |
| 回报记录号 ReportIndex | 按分区（SetID）从 1 开始**连续编号**，网关发送时分配 |

#### 支持的消息类型

- 会话层：Logon(40)、Logout(41)、Heartbeat(33)、平台状态(209)、执行报告信息(208)、序号同步(206)/序号同步响应(207)
- 业务层：新订单 58、申报响应（执行报告）32、成交回报 103、订单拒绝 204、撤单 61 → 撤单成功 32(ExecType=4) / 撤单失败（撤单拒绝）59（按原单状态，见 4.5）

### 6.3 上海新债券网关（上交所债券平台 Binary 1.90）

新债券平台的报文结构、会话流程、消息类型、编码规则（报文头、校验和、价格/数量放大、心跳、分区序号同步）
**与上海竞价网关完全一致**（参见 6.2），仅以下业务参数不同：

| 项 | 新债券平台 | （对比）竞价平台 |
| --- | --- | --- |
| PlatformID | 2（新债券平台） | 0（竞价平台） |
| SetID（分区号） | 默认 801 | 默认 1 |
| BizID（业务类别） | 1=债券现券竞价、2=债券质押式回购 | 100010 |
| 协议版本 | 最低 1.90 | "0.50" |
| OrdType（订单类型） | 仅支持 2=限价 | — |

会话流程、支持的消息类型、回报策略均与 6.2 相同。

## 7. 常见问题（FAQ）

**Q1：启动网关时提示端口相关错误？**
该端口已被其他程序（或另一个平台）占用。换一个端口，或用
`netstat -ano | findstr :端口号` 查找占用者。新建平台时程序会自动
从 10001 起挑选空闲端口。

**Q2：柜台连不上平台？**
按顺序检查：① 网关是否已启动（卡片显示"监听中"）；② 监听地址是否为
`0.0.0.0`（`127.0.0.1` 只允许本机连接）；③ Windows 防火墙是否放行了
该端口或本程序；④ 柜台连接的 IP/端口是否正确。

**Q3：柜台连上了但登录失败？**
查看日志面板的具体原因。若平台开启了「校验登录密码」，柜台 Logon
报文中的 Password 必须与平台配置一致。

**Q4：右上角显示「远程后端·连接中…」？**
远程模式下未连上 simx-server。检查服务器上 simx-server 是否在运行、
`simx.config.json` 中的 `remoteUrl` 地址端口是否正确、网络/防火墙是否放行。
程序会每 2 秒自动重连，服务恢复后自动接上。

**Q5：委托发出去了但一直收不到成交回报？**
检查平台策略：「只回确认回报」模式只回确认；「自动拒单」模式只回拒绝。
另外确认成交延迟没有设置得过大。

**Q6：配置保存在哪里？换机器如何迁移？**
所有网关/平台配置保存在数据目录的 `gateways.json`（单机模式为 exe 同目录，
远程模式为 simx-server 所在目录）。复制该文件到新环境即可迁移。

**Q7：统计数字和柜台对不上？**
界面数据每秒刷新一次，最多有 1 秒延迟；顶栏"拒单"是执行报告拒绝与
业务拒绝两类之和。若需从零核对，先点「重置统计」再开始测试。

**Q8：柜台断线后重连不上，或第二个柜台连不上？**
每个平台同一时刻只服务一个柜台连接：若旧连接尚未断开（服务端还未感知到断线），新连接会被直接拒绝。
请确认旧连接已完全关闭后稍候重试；若断线后立即重连仍被拒，等 1~2 秒让服务端完成连接清理即可。

**Q9：如何让后端启动后自动开启网关（无人值守）？**
启动 simx-server 时加 `--auto-start` 参数即可：后端启动完成后自动恢复**上次运行中**
的网关（启停状态记在 `gateways.json` 的 `wasRunning` 字段，只启动上次退出时仍在运行的网关），
无需打开界面手动启动（定时启停 + 自动开网关组合见《构建调试手册》6 节）。
桌面端启动程序时附带 `--auto-start` 参数同样生效。

**Q10：怎么知道有没有新版本？如何升级？**
① 点顶栏「ⓘ 关于」→「检查更新」手动查；② 程序启动 3 秒后也会自动查一次——
发现新版会弹窗，点「下载并安装」自动下载并启动安装程序。前提是在「后端连接设置」
里填了「更新服务器地址」，且服务器上放好了发布目录和版本号文件（见 5.5 节）。
远程后端自查：启动时加 `--update-url` 参数，日志会打印版本对比结果。
想直接查看后端版本号：执行 `./simx-server --version`（启动日志首行也会
打印版本，如 `SimuXchange 后端已启动 v2.0.0`）。

## 8. CLI 命令行工具（自动测试）

模拟撮合界面适合人工联调，自动化测试（回归、CI、定时批量跑用例）则需要
可被脚本逐条调用的命令入口。`simx-cli` 就是这样的命令行工具：它连接已启动的
simx-server（WebSocket 控制口），把"查状态 / 改策略 / 手动回报"等操作做成
子命令，一次调用做一件事、以退出码和 JSON 反馈结果。**引擎与 simx-server
本身不因 CLI 有任何改动**，CLI 只是现行控制协议的客户端，界面能做的控制
操作 CLI 都能做（网关创建等配置结构类操作仍建议用界面）。

> **完整用法（每个子命令的示例）见独立文档 `docs/CLI工具使用手册.md`**，
> 本章只给速查。

### 8.1 构建与启动

```powershell
cargo build --release -p simx-cli        # Windows，产物 target\release\simx-cli.exe
```

CLI 不监听任何端口，只需目标 simx-server 已启动并可达：

- 首次连指定服务器：`simx-cli login --url ws://<IP>:<端口>/ws`——探活
  通过后地址保存到用户主目录 `.simx-cli.json`，**之后所有命令免 `--url`**
  （单条命令可用 `--url` 临时覆盖；`logout` 清除保存值）；
- 从未登录过则默认连 `ws://127.0.0.1:9800/ws`（本机）；
- 需要长时间无人值守时可给 simx-server 加 `--auto-start`（见 Q9），
  配合 CLI 实现"开机自动恢复网关 → 脚本自动测试"。

### 8.2 全局参数与退出码

```
simx-cli [--url <地址>] [--json] [--timeout 毫秒] <子命令> ...
simx-cli login|logout ...                     # 地址保存/清除（见 8.1）
```

| 选项 | 说明 |
| --- | --- |
| `--url` | 本次命令临时指定的地址（覆盖 login 保存值，仅本次有效） |
| `--json` | 原样输出后端 JSON 响应（`{"ok":true,"data":...}`），脚本用 jq 解析 |
| `--timeout` | 单次请求超时毫秒，默认 10000 |

另有 `-V` / `--version`（打印版本号，如 `simx-cli 2.0.0`）与 `-h` / `--help`
（打印子命令速查），两者不连服务器、直接退出。

以上参数放在子命令前后均可；退出码：**0** 成功；**1** 后端返回错误 /
连接失败 / 超时；**2** 命令行参数错误（如非法模式名）。失败时错误文本
输出到 stderr；`--json` 模式下即使失败也会在 stdout 打印一行标准 JSON
（便于脚本统一解析）。

网关与平台参数（`--gateway` / `--platform`）**同时支持 id 与名称**
（自动解析成后端接受的 id；名称以 `snapshot` 输出的为准）。网关与
平台名称**允许重复**：名称命中多个时 CLI 会报错并列出候选 id（绝不
默默取第一个），改用 id 定位即可——所以自动化脚本里优先写 id。

### 8.3 子命令速查

**查询**

```text
simx-cli snapshot [--gateway <id或名称>]        # 网关/平台运行状态、端口与统计
simx-cli orders  --gateway G --platform P       # 订单缓存明细表（手动回报前查委托编号）
                   [--status new|partial|filled|cancelled|rejected] [--limit N]
simx-cli health                                  # 探活
```

**回报策略（等价界面"编辑平台→策略"，运行中实时生效并持久化）**

```text
simx-cli set-strategy --gateway G --platform P [--mode <模式>] [其它字段覆盖]
```

- 未传的参数保持服务器当前值（基于快照做增量覆盖，只改一个字段也安全）；
- `--mode` 取值与界面一致：`fullSingle` / `fullSplit` / `partialSingle` /
  `partialSplit` / `noAutoReply`（不自动回复）/ `ackOnly`（只回确认）/
  `reject`（拒单）/ `luaScript`（Lua 脚本回报）；
- 其它字段：`--split-min N --split-max N --price-tick X`（拆单）、
  `--reject-via executionReport|businessReject --reject-reason N --reject-text 文本`、
  `--ack-delay 毫秒[,毫秒] --trade-delay ... --cancel-delay ...`（延迟，单值=固定，
  两值=区间随机）、`--cancel-mode default|alwaysSuccess|alwaysReject
  --cancel-reject-reason N --cancel-front-reject`（撤单模式）、
  `--lua-script 脚本文本|@文件`（Lua 模式脚本，"@"前缀从文件读取）；
- `--strategy-json <文件>`：用 JSON 文件整体替换整套策略（内容即策略对象，
  字段 camelCase、mode 必填），再叠加其余命令行覆盖；
- Lua 模式下保存前自动做语法校验（也可单独用 validate-lua 子命令提前自检）。

**手动回报（等价界面"订单弹窗→回复"；委托须在缓存且在途）**

```text
simx-cli send --gateway G --platform P --order <委托编号> <kind> [--qty N] [--price X] [--reason N] [--front-reject]
```

- `<kind>`：`ack` 确认 / `trade` 成交 / `reject` 拒单 / `cancel` 撤单成功；
- `trade` 不传 `--qty/--price` 时按剩余量全成、委托价成交（与界面一致）；
- `reject` 不传 `--reason` 时按网关分类取默认原因码（深圳 20009 / 上海 1025）；
  `--front-reject` 改发业务拒绝消息；
- 回报统一走当前活动柜台连接（与界面"手动回复"行为一致）。

**网关管理 / 服务器地址**

```text
simx-cli start --gateway G / stop --gateway G / reset-stats --gateway G
simx-cli validate-lua "脚本|@文件"          # 只校验语法，不保存
simx-cli login --url ws://<IP>:<端口>/ws   # 登录（探活+保存地址），此后免 --url
simx-cli logout                            # 清除保存的地址，恢复默认本机
```

### 8.4 自动化测试场景示例（PowerShell 脚本）

```powershell
$cli = ".\simx-cli.exe"

# 1. 登录一次（探活并保存地址），之后全部命令免 --url
& $cli login --url ws://192.168.1.10:9800/ws
#    启动后端（本机）
#    .\simx-server.exe --listen 0.0.0.0:9800 --auto-start

# 2. 确认后端在线与网关切好（按名称定位）
& $cli health
& $cli snapshot

# 3. 把平台切到"只回确认 + 80 毫秒固定延迟"，重启前先确认脚本自然
& $cli set-strategy --gateway 竞价网关A --platform 平台1 --mode ackOnly --ack-delay 80

# 4. （柜台侧）下单 → 查订单拿到委托编号
& $cli orders --gateway 竞价网关A --platform 平台1 | Select-String "已报"

# 5. 对某笔委托手动回一笔 500 股 @ 10.01 的成交
& $cli send --gateway 竞价网关A --platform 平台1 --order CL0001234 trade --qty 500 --price 10.01

# 6. 校验订单终态（退出码 0 才继续）
& $cli orders --gateway 竞价网关A --platform 平台1 --status filled; if ($LASTEXITCODE -ne 0) { exit 1 }

# 7. 用例结束清理：重置统计、停网关
& $cli reset-stats --gateway 竞价网关A
& $cli stop --gateway 竞价网关A
```

要点：脚本里用 `--json` + jq/python 解析时，判断成败优先看**退出码**，
内容校验看 stdout 的 JSON；命令与后台解耦，CLI 进程不会常驻。
更多场景（拆分成交、Lua 回报、CI 流水线写法、FAQ）见独立文档
`docs/CLI工具使用手册.md`。
