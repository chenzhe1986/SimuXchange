# SimuXchange 产品使用手册

> SimuXchange 是一款**模拟交易所交易网关（TGW）**的测试工具：
> 它假扮真实的交易所网关，接受您的柜台系统（OMS）按交易所 Binary 协议发来的
> TCP 连接和委托，并按您配置的策略回送确认回报、成交回报或拒单——
> 让柜台系统不必连接真实交易所就能完成联调测试。
>
> 支持三类网关（新建网关时选择分类）：**深圳统一网关**（深交所 Binary 协议）、
> **上海竞价网关**（上交所竞价平台 Binary 0.54 协议）与**上海新债券网关**（上交所债券平台 Binary 1.90 协议）。
>
> 本软件**没有真实订单簿与撮合**，所有回报均为按策略模拟生成。

## 1. 安装与启动

### 1.1 单机模式（最常用）

两种方式任选其一：

| 方式 | 操作 |
| --- | --- |
| 免安装版 | 将 `simuxchange.exe` 与 `simx.config.json` 放同一目录，双击 exe 启动 |
| 安装包 | 运行 `SimuXchange_x64-setup.exe` 按提示安装 |

安装包还自带 **Linux 后端**（安装目录的 `Linux\simx-server`，musl 静态编译），
可拷到 Linux 服务器做远程部署（见 1.2 节），无需另找安装文件。

首次启动后，程序会在 exe 同目录自动生成 `gateways.json` 保存您的网关配置，
下次启动自动恢复。

### 1.2 远程模式（引擎部署在服务器上）

适合场景：模拟网关跑在测试服务器/Linux 上，本机只做操作界面。

1. 在服务器上运行独立后端（推荐用 crontab 定时启停，早 8 点开晚 10 点关，
   见《构建调试手册》6 节）：
   ```
   ~/simx-server/simx-server --listen 0.0.0.0:9800
   ```
   加 `--auto-start` 参数后，后端启动完成会**自动恢复上次运行中**的网关（引擎把
   网关启停状态记在 `gateways.json` 的 `wasRunning` 字段，只启动上次退出时仍在运行的网关），
   无需再打开界面手动启动（适合定时启停的无人值守场景）；不带该参数则所有网关都不
   会自动启动：
   ```
   ~/simx-server/simx-server --listen 0.0.0.0:9800 --auto-start
   ```
2. 启动桌面端，点击右上角**状态徽章**（原来只显示“本地引擎/远程后端”的地方），
   在「后端连接设置」弹窗里可**添加多个远程后端**：只需填**服务器地址**
   （IP 或域名，如 `192.168.1.10`；地址里带端口如 `192.168.1.10:9810` 也可），
   **端口**默认 9800，系统自动补 `ws://` 前缀与 `/ws` 路径并实时预览完整地址，
   **名称可选**（留空自动按地址生成），添加后自动切换过去；以后点列表项即可随时切换。
   保存后立即生效，并写入程序目录的 `simx.config.json`（下次启动自动生效）；
   想回到单机模式，点列表里的「本地引擎」即可，全程无需改文件。
3. 徽章显示「<名称>·已连接」即成功。

远程模式下，引擎运行在服务器上：网关配置保存在服务器的 `gateways.json`，
报文文件写在服务器的 `packets/` 目录；界面仅作遥控台，所有操作
（启停、新建网关、改配置、看统计、看报文）都通过网络实时执行。

断线后界面会**每 2 秒自动重连**，服务恢复后无需手动操作。
若启动时已处于远程模式但连不上服务器，徽章显示「<名称>·连接中…」，
此时仍可点击徽章切回本地引擎。

```

├───────────┬────────────────────────────────────────────────────┤

└────────────────────────────────────────────────────────────────┘
```

| 区域 | 内容 |
| --- | --- |
| 顶栏 | 全局统计（所有平台汇总）、引擎连接状态徽章、赞赏按钮、版本信息按钮（ⓘ）、配色按钮（◐）、窗口控制；空白处可拖动窗口 |
| 左侧栏 | 交易网关列表，绿点=运行中；点击选中，右键有快捷菜单 |
| 主区 | 选中网关的操作按钮和平台卡片网格 |
| 底部 | 运行日志面板，可折叠、按级别过滤 |

**概念说明**：一个**网关**是一组平台的集合，整体启动/停止；
一个**平台** = 一个 TCP 监听端口，柜台连接的就是平台的端口。
可以建多个网关模拟多套环境，互不干扰。

**网关分类**：新建网关时需选择分类，决定该网关下所有平台说哪套协议：

| 网关分类 | 协议 | 平台类型 |
| --- | --- | --- |
| 深圳统一网关 | 深交所 Binary | 6 种平台（现货集中竞价等） |
| 上海竞价网关 | 上交所竞价平台 Binary 0.54 | 竞价平台（PlatformID=0） |
| 上海新债券网关 | 上交所债券平台 Binary 1.90 | 新债券平台（PlatformID=2） |

分类**创建后不可修改**（重命名时分类下拉框为只读）；需改分类请新建网关。

## 3. 快速上手（四步开始联调）

1. **新建网关**：左侧栏点「＋ 新建」，输入名称、选择**网关分类**（深圳统一网关 /
   上海竞价网关 / 上海新债券网关）后保存。分类决定该网关用哪套协议，创建后不可改。
2. **添加平台**：主区点「＋ 添加平台」，至少确认两项——
   **监听端口**（柜台要连的端口，自动预填空闲端口）和**回报模式**
   （默认"全部成交（单笔）"），其余保持默认即可，点「保存」。
3. **启动网关**：点「▶ 启动网关」。平台卡片显示绿点「监听中」即就绪。
4. **柜台接入**：让柜台系统连接 `本机IP:平台端口`，完成 Logon 后即可发送委托，
   界面实时显示连接、统计和日志。

> ⚠️ 网关**运行中**：**模拟回报策略与回报延迟**可直接修改，保存后**实时生效**
> （无需停止网关，见 4.3/4.4）；但**不允许添加/删除平台或删除网关**
> （避免端口状态错乱），相关按钮会置灰；其余平台配置（端口、密码等）
> 需停止网关后修改。

## 4. 平台配置详解

在平台编辑弹窗中可配置：

### 4.1 基础信息

| 配置项 | 说明 |
| --- | --- |
| 平台名称 | 仅用于界面显示 |
| 平台类型 (PlatformID) | **选项随网关分类变化**：深圳统一网关为 1=现货集中竞价、2=综合金融服务、3=非交易处理、4=衍生品集中竞价、5=国际市场互联、6=固定收益；上海竞价网关仅 0=竞价平台；上海新债券网关仅 2=新债券平台 |
| 监听地址 | `0.0.0.0`=所有网卡均可接入；`127.0.0.1`=仅本机 |
| 监听端口 | 柜台连接的 TCP 端口，多个平台不能重复 |
| 网关 CompID | 回报中的 SenderCompID（网关的机构代码） |
| 平台分区号 (PartitionNo) | 回填到回报报文的分区号字段（上交所为 SetID） |
| 校验登录密码 | 勾选后，柜台 Logon 中的 Password 必须与此处一致，否则拒绝登录（**上海竞价/新债券网关登录无密码字段，故无此选项**） |
| 展示收发报文 | **默认勾选**。勾选后，平台卡片出现「报文」按钮，点击弹出窗口实时查看该平台全部连接的收发报文（按交易所字段名解析 + 收发颜色区分，见 4.2）；同时**自动持久化**到数据目录 `packets/` 下的日志文件，无需单独设置 |
| 缓存订单 | **默认开启**。开启后，平台收到的所有委托（及其后续回报）会被缓存下来，可通过平台卡片上的「订单」按钮随时查看全部订单及其实时状态（见 4.5）；关闭后不缓存、卡片不显示「订单」按钮 |

> ⚠️ **单连接限制**：每个平台同一时刻只接受**一个柜台连接**。已有连接时，新连接会被直接拒绝
> （柜台侧表现为连接建立后立即被断开）；原连接断开后可随时重新接入。

### 4.2 报文捕获（展示收发报文 + 字段解析 + 自动持久化）

「展示收发报文」为**单一开关（默认勾选）**：勾选后同时开启界面展示、按交易所字段名解析、持久化到文件三件事，无需分别设置。

| 效果 | 说明 |
| --- | --- |
| **界面展示** | 平台卡片连接概览行出现「报文」按钮，点击弹出**收发报文窗口**：该平台**所有历史连接**收发的报文按接入时间顺序展示，**每个连接的报文独占一段**，段首是明显的分组标题（如 `连接 #1 · 127.0.0.1:52300 · 20:35:26 接入 · 在线/已断开 · N 条`），段与段之间以虚线分隔，新报文自动滚动到底部 |
| **字段解析** | 每条报文在原始字节下方按**交易所字段名**逐字段解析展示（如深交所报文的 `MsgType`、`ClOrdID`、`SecurityID`、`Side`、`Price`、`OrderQty` 等）。解析字段与原始报文用**不同字体**区分层次；**绿色=收到的报文，琥珀色=发送的报文**，一眼分清方向 |
| **持久化** | 报文在记录内存的同时逐行追加写入数据目录 `packets/` 下的日志文件，**文件内容与弹窗展示一致**（原始报文行下方即解析字段缩进行），连接断开后文件保留，可随时用任意文本编辑器打开查看 |

每条报文的展示格式（弹窗与文件相同）：

```
20:35:26.583 RECV  FE 3F 86 0C 18 00 00 00 ...   ← 原始报文（大写十六进制字节）
                   MsgType                 : 100101 (现货新订单)
                   ClOrdID                 : OMS000123
                   SecurityID              : 000001
                   Side                    : 1 (买)
                   Price                   : 10.0100
                   OrderQty                : 100
```

> 解析失败或未知消息类型时只展示原始报文行；报文文件**按日期 → 网关名_平台名分层存放**，一眼定位某天某平台某连接的报文：

```
packets/
└── 20260814/                      ← 按日期分文件夹（YYYYMMDD）
    └── 分组7深圳模拟撮合1_现货集中竞价交易平台/   ← 日期下按“网关名_平台名”分文件夹
        └── pkg_203526_ip-192_168_1_100_port-8080.log   ← 每条连接一个文件
```

文件名格式：`pkg_<接入时分秒>_ip-<客户端IP点转下划线>_port-<客户端端口>.log`（如
`pkg_203526_ip-192_168_1_100_port-8080.log` = 20:35:26 接入的 192.168.1.100:8080 柜台）。

> 提示：即使中途关闭报文弹窗，报文仍会持续写入文件；历史连接断开后其文件保留，随时可回看。

### 4.3 模拟回报策略（七种模式）

| 模式 | 收到委托后的行为 |
| --- | --- |
| 全部成交（单笔） | 1 条确认 + 1 条全量成交（成交价=委托价） |
| 全部成交（多笔拆单） | 1 条确认 + N 条成交，数量随机拆分；价格按档位逐笔变化——买单从委托价逐档递减、卖单逐档递增（模拟"先吃掉便宜的对手盘"） |
| 部分成交（单笔） | 1 条确认 + 1 条随机数量的部分成交（剩余量保持挂单状态） |
| 部分成交（多笔拆单） | 1 条确认 + N 条部分成交 |
| 自定义成交 | 1 条确认 + 严格按您配置的"数量/价格"明细逐笔成交 |
| 不成交挂单（只回确认） | 只回 1 条确认，不产生成交 |
| 拒单 | 回执行报告拒绝（200102, ExecType=8）或业务拒绝消息（MsgType=4），二选一；原因码和说明文字可配置 |

> **策略支持热更新**：网关**运行中**修改策略或回报延迟，保存后对**后续委托实时生效**，无需停止网关（其余平台配置如端口、密码等仍需停止后修改）。

拆单模式的附加参数：
- **拆单笔数**：在最小~最大之间随机（如 3~5 表示每笔委托拆成 3 到 5 笔成交）
- **价格档位**：逐笔成交的价差（元），设 0 则所有笔都按委托价成交

### 4.4 回报延迟

确认回报和成交回报可分别设置延迟（毫秒）：

| 设置 | 效果 |
| --- | --- |
| 最小 = 最大 = 0 | 同步回报（收到委托立即回，顺序严格） |
| 最小 = 最大 > 0 | 固定延迟 |
| 最小 < 最大 | 每笔在区间内随机延迟（更接近真实网络） |

拆单时每笔成交单独抽样延迟。拒单模式无成交，不显示成交延迟。

### 4.5 订单缓存与撤单回复

「缓存订单」默认开启：平台收到的每笔委托都会登记一条记录，后续确认/成交/拒单/撤单回报会实时更新其状态，数据保存在内存中（重启后清空）。

- **查看订单**：平台卡片上出现「订单」按钮（开启缓存后才有），点击弹出订单列表弹窗，展示每笔委托的**时间、委托编号、交易所订单号、证券、方向、价格、委托量、成交量、剩余量、状态**；列表每 1 秒自动刷新；
- **只显示在途订单**：弹窗右上角勾选后，列表只保留**已报 / 部分成交**的在途订单（全成/已拒/已撤为终态订单，被隐藏）；
- **状态含义**：已报（new）= 已确认未成交；部分成交（partial）= 成交了一部分、剩余仍挂单；全部成交（filled）、已撤（cancelled）、已拒绝（rejected）为终态。

**撤单回复规则**：收到柜台撤单请求后，按原订单当前状态回复——

| 原订单状态 | 撤单结果 | 回报 |
| --- | --- | --- |
| 在途（已报 / 部分成交） | **撤单成功** | 执行报告 ExecType=4（已撤），订单状态变为「已撤」 |
| 终态（全部成交 / 已拒绝 / 已撤） | **撤单失败** | 撤单失败消息（深交所 290008 / 上交所 59） |

**手动回复在途订单**：订单列表弹窗中，**已报 / 部分成交**的在途订单行末有「回复」按钮，点击在行下方展开手动回复面板，可主动向柜台补发三种回报（发送后订单进入终态，不能再回复）：

| 回报 | 可配置项 | 默认值 | 说明 |
| --- | --- | --- | --- |
| **成交回报** | 成交数量、成交价格 | 剩余量（全成）、委托价 | 按自然单位填写（股/元）；数量超过剩余量时按剩余量全成 |
| **拒单回报** | 拒单原因代码 | 1 | 以执行报告（ExecType=8）形式发出 |
| **撤单成功回报** | 无 | — | 剩余量全部撤掉，执行报告 ExecType=4 |

> 手动回报统一发往**当前活动连接**（历史连接发来的订单同样走当前连接）；手动成交/拒单会计入平台统计（成交/拒单），手动撤单成功不计入「撤单」计数（那是撤单请求的计数）。

## 5. 日常操作

### 5.1 右键菜单

界面各区域均支持右键快捷操作：

| 右键位置 | 可用操作 |
| --- | --- |
| 侧栏网关项 | 启动/停止、添加平台、重命名、重置统计、删除网关 |
| 平台卡片 | 编辑平台、复制监听地址、删除平台 |
| 空白区域 | 新建网关、添加平台、刷新 |
| 日志面板 | 复制选中内容、清空日志 |
| 输入框 | 剪切、复制、粘贴、全选 |

不可用的操作会自动置灰（如运行中的网关不能删除）。按 `Esc` 关闭菜单。

### 5.2 查看连接与统计

- **平台卡片**上实时显示：委托 / 确认 / 成交 / 拒单 / 撤单 五项计数；
- 开启「缓存订单」的平台，卡片上还有「订单」按钮，点击弹出**订单列表弹窗**：展示该平台收到的全部委托及其实时状态（每 1 秒自动刷新），勾选「只显示在途订单」可只保留已报/部分成交的订单（见 4.5）；
- 点击卡片底部「连接 N（已登录 M）」行可**展开连接明细**：
  每行显示对方 IP:端口、柜台 Logon 报的机构代码、接入时间；
  绿点=已完成登录，灰点=TCP 已连但未登录；
- 平台开启「展示收发报文」后，连接概览行出现「报文」按钮，点击弹出**平台级收发报文窗口**：该平台所有历史连接的报文按接入时间顺序分组展示，每条报文在原始字节下方同时展示按交易所字段名的解析（收发颜色区分、字体层次分明，见 4.2）；
- **顶栏**显示所有平台的汇总统计；
- 「重置统计」将当前网关所有平台计数清零（不断开连接，订单序号不重置）。

数据每秒自动刷新，无需手动操作。

### 5.3 日志面板

- 点「运行日志」标题可折叠/展开面板；

### 5.5 版本信息与自动升级

**查看版本**：点击顶栏右侧的 **ⓘ 关于**按钮，弹窗显示当前版本号（如 1.0.0）
与更新说明，以及「检查更新」按钮。

**配置更新服务器**：点击右上角状态徽章（本地引擎/远程后端），在「后端连接设置」
弹窗里填「更新服务器地址」（如 `http://192.168.1.10/update`，留空则不检查更新），
保存后立即生效并写入 `simx.config.json`。

**自动检查**：程序启动 3 秒后自动向更新服务器拉取 `version.json`；发现新版本时
弹出提示（版本号 + 更新说明），点「下载并安装」自动把安装包下载到本机
“下载”文件夹并启动安装程序，按提示覆盖安装即可（配置不丢）。
检查失败（服务器没开、地址填错等）**静默忽略**，不影响正常使用。

**服务器端发布新版**（二选一）：

1. **升级服务器程序（推荐）**：服务器上运行 `simx-update-server`（见《构建调试手册》6.6 节），
   浏览器打开管理页面，上传新安装包（文件名须含版本号，如
   `SimuXchange_1.1.0_x64-setup.exe`）与更新说明即可，`version.json` 自动生成；
2. **静态目录**：把文件放到任意 HTTP 可访问的目录（见下）。

静态目录方式下，把以下文件放到更新目录：

```json
{
    "version": "1.1.0",
    "notes": ["新增 XX 功能", "修复 XX 问题"],
    "winInstaller": "SimuXchange_1.1.0_x64-setup.exe",
    "linuxServer": "simx-server"
}
```

`version` 大于当前版本号（数字点分比较）即提示升级。
**远程后端的自检**：服务器上启动 simx-server 时加 `--update-url http://<服务器IP>/update`，
启动日志会打印“发现新版本 / 已是最新版本”（只提示不自动替换，请按提示手动部署）。
用升级服务器程序时填 `http://<服务器IP>:8080` 即可。

## 6. 柜台对接说明（给对接方的技术参考）

柜台系统按对应交易所的 **Binary 协议**（均大端序）连接平台端口。以下按网关分类分别说明。

### 6.1 深圳统一网关（深交所 Binary）

#### 会话流程

```
柜台                          SimuXchange
 │ ── Logon(1) ──────────────────▶ │   校验密码（若开启）
 │ ◀────────────── Logon(1) ────── │   双方 CompID 对调
 │ ◀────────────── 平台信息(9) ──── │
 │ ◀────────────── 平台状态(6) ──── │
 │ ⇄  Heartbeat(3) 按 Logon 协商的间隔互发
 │ ── 新订单 100101 ──────────────▶ │
 │ ◀────── 确认 200102 / 成交 200115 / 拒单 ── │   按平台策略
 │ ── 撤单 190007 ────────────────▶ │
 │ ◀─ 执行报告 200102(ExecType=4) ─ │   在途订单 → 撤单成功
 │ ◀────────── 撤单失败 290008 ──── │   终态订单 → 撤单失败（需开启缓存订单）
```

#### 编码要点

| 项 | 规则 |
| --- | --- |
| 报文结构 | MsgType(4) + BodyLength(4) + Body + Checksum(4)，均大端序 |
| 定长字符串 | 右补空格 |
| 价格 Price N13(4) | 实际价格 × 10000（12.34 元 → 123400） |
| 数量 Qty N15(2) | 实际股数 × 100（500 股 → 50000） |
| 心跳超时 | 超过心跳间隔 3 倍未收到任何报文，连接被断开 |

#### 支持的消息类型

- 会话层：Logon(1)、Logout(2)、Heartbeat(3)、平台状态(6)、平台信息(9)
- 业务层：新订单 100101、确认回报 200102、成交回报 200115、
  业务拒绝(4)、撤单 190007 → 撤单成功 200102(ExecType=4) / 撤单失败 290008（按原单状态，见 4.5）

### 6.2 上海竞价网关（上交所竞价平台 Binary 0.54）

#### 会话流程

```
柜台                          SimuXchange
 │ ── Logon(40) ─────────────────▶ │   无密码字段
 │ ◀───────────── Logon(40) ────── │   双方 CompID 对调
 │ ◀───────────── 平台状态(209) ─── │
 │ ◀──────────── 执行报告信息(208) ─ │
 │ ── 分区序号同步 206 ────────────▶ │   登录后必须先做
 │ ◀──────── 序号同步响应 207 ────── │   之后才推送执行报告
 │ ⇄  Heartbeat(33) 间隔 5~60 秒互发
 │ ── 新订单 58 ──────────────────▶ │
 │ ◀──── 申报响应 32 / 成交 103 / 拒单 204 ── │   按平台策略
 │ ── 撤单 61 ────────────────────▶ │
 │ ◀──────── 执行报告 32(ExecType=4) ── │   在途订单 → 撤单成功
 │ ◀────────── 撤单失败 59 ──────── │   终态订单 → 撤单失败（需开启缓存订单）
```

#### 编码要点

| 项 | 规则 |
| --- | --- |
| 报文结构 | MsgType(4) + MsgSeqNum(8) + MsgBodyLen(4)（16 字节头）+ Body + Checksum(4)，均大端序 |
| 校验和 | 报文所有字节按 uint8 累加（自然溢出取低 8 位） |
| 消息序号 | MsgSeqNum 由网关发送时递增赋值 |
| 价格 Price N13(5) | 实际价格 × 100000（12.34 元 → 1234000） |
| 数量 Qty N15(3) | 实际股数 × 1000（500 股 → 500000） |
| 登录门槛 | 登录后需先完成分区序号同步（206→207），同步前的执行报告会缓存、同步后补发 |
| 心跳 | HeartBtInt 协商区间 5~60 秒 |

#### 支持的消息类型

- 会话层：Logon(40)、Logout(41)、Heartbeat(33)、平台状态(209)、执行报告信息(208)、序号同步(206)/序号同步响应(207)
- 业务层：新订单 58、申报响应（执行报告）32、成交回报 103、订单拒绝 204、撤单 61 → 撤单成功 32(ExecType=4) / 撤单失败（撤单拒绝）59（按原单状态，见 4.5）

### 6.3 上海新债券网关（上交所债券平台 Binary 1.90）

新债券平台的报文结构、会话流程、消息类型、编码规则（报文头、校验和、价格/数量放大、心跳、分区序号同步）
**与上海竞价网关完全一致**（参见 6.2），仅以下业务参数不同：

| 项 | 新债券平台 | （对比）竞价平台 |
| --- | --- | --- |
| PlatformID | 2（新债券平台） | 0（竞价平台） |
| SetID（分区号） | 默认 801 | 默认 1 |
| BizID（业务类别） | 1=债券现券竞价、2=债券质押式回购 | 100010 |
| 协议版本 | 最低 1.90 | "0.50" |
| OrdType（订单类型） | 仅支持 2=限价 | — |

会话流程、支持的消息类型、回报策略均与 6.2 相同。

## 7. 常见问题（FAQ）

**Q1：启动网关时提示端口相关错误？**
该端口已被其他程序（或另一个平台）占用。换一个端口，或用
`netstat -ano | findstr :端口号` 查找占用者。新建平台时程序会自动
从 10001 起挑选空闲端口。

**Q2：柜台连不上平台？**
按顺序检查：① 网关是否已启动（卡片显示"监听中"）；② 监听地址是否为
`0.0.0.0`（`127.0.0.1` 只允许本机连接）；③ Windows 防火墙是否放行了
该端口或本程序；④ 柜台连接的 IP/端口是否正确。

**Q3：柜台连上了但登录失败？**
查看日志面板的具体原因。若平台开启了「校验登录密码」，柜台 Logon
报文中的 Password 必须与平台配置一致。

**Q4：右上角显示「远程后端·连接中…」？**
远程模式下未连上 simx-server。检查服务器上 simx-server 是否在运行、
`simx.config.json` 中的 `remoteUrl` 地址端口是否正确、网络/防火墙是否放行。
程序会每 2 秒自动重连，服务恢复后自动接上。

**Q5：委托发出去了但一直收不到成交回报？**
检查平台策略：「不成交挂单」模式只回确认；「拒单」模式只回拒绝。
另外确认成交延迟没有设置得过大。

**Q6：配置保存在哪里？换机器如何迁移？**
所有网关/平台配置保存在数据目录的 `gateways.json`（单机模式为 exe 同目录，
远程模式为 simx-server 所在目录）。复制该文件到新环境即可迁移。

**Q7：统计数字和柜台对不上？**
界面数据每秒刷新一次，最多有 1 秒延迟；顶栏"拒单"是执行报告拒绝与
业务拒绝两类之和。若需从零核对，先点「重置统计」再开始测试。

**Q8：柜台断线后重连不上，或第二个柜台连不上？**
每个平台同一时刻只服务一个柜台连接：若旧连接尚未断开（服务端还未感知到断线），新连接会被直接拒绝。
请确认旧连接已完全关闭后稍候重试；若断线后立即重连仍被拒，等 1~2 秒让服务端完成连接清理即可。

**Q9：如何让后端启动后自动开启网关（无人值守）？**
启动 simx-server 时加 `--auto-start` 参数即可：后端启动完成后自动恢复**上次运行中**
的网关（启停状态记在 `gateways.json` 的 `wasRunning` 字段，只启动上次退出时仍在运行的网关），
无需打开界面手动启动（定时启停 + 自动开网关组合见《构建调试手册》6 节）。
桌面端启动程序时附带 `--auto-start` 参数同样生效。

**Q10：怎么知道有没有新版本？如何升级？**
① 点顶栏「ⓘ 关于」→「检查更新」手动查；② 程序启动 3 秒后也会自动查一次——
发现新版会弹窗，点「下载并安装」自动下载并启动安装程序。前提是在「后端连接设置」
里填了「更新服务器地址」，且服务器上放好了新安装包和 `version.json`（见 5.5 节）。
远程后端自查：启动时加 `--update-url` 参数，日志会打印版本对比结果。
