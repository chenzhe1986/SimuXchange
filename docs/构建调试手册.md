# SimuXchange 构建调试手册

> 本手册面向需要**从源码手动编译、调试、打包**本项目的开发者。
> 按顺序照做即可完成从零环境到发布产物的全过程；文末汇总了实际开发中踩过的所有坑。

---

## 1. 项目概览

SimuXchange 是跨平台模拟撮合软件：模拟交易所交易网关（TGW），接受柜台（OMS）的
Binary 协议 TCP 连接，按配置策略回送确认/成交回报。支持三类网关（新建时选择分类）：
**深圳统一网关**（深交所 Binary，sz）、**上海竞价网关**（上交所竞价平台 Binary 0.54，shjj）
与**上海新债券网关**（上交所债券平台 Binary 1.90，shbond），
三套协议代码按后缀分文件存放（`*_sz.rs` / `*_shjj.rs` / `*_shbond.rs`）。技术栈：

| 层 | 技术 | 说明 |
| --- | --- | --- |
| 核心引擎 | Rust（tokio 异步） | `crates/simx-core`，协议编解码 + 会话 + 回报策略 |
| 桌面壳 | Tauri 2 | `src-tauri/`，内嵌引擎，包名 `simuxchange` |
| 独立后端 | Rust + axum WebSocket | `crates/simx-server`，服务器远程部署用 |
| 前端界面 | Vue 3 + TypeScript + Vite 6 | `src/` |

```
SimuXchange/
├─ crates/
│  ├─ simx-core/        # 核心库（协议、会话、策略、统计、报文捕获）
│  │   ├─ src/sz/       # 深圳统一网关：protocol.rs / session.rs / strategy.rs
│  │   ├─ src/shjj/     # 上海竞价网关：protocol.rs / session.rs / strategy.rs
│  │   ├─ src/shbond/   # 上海新债券网关：protocol.rs / session.rs / strategy.rs
│  │   └─ tests/        # e2e_sz.rs / e2e_shjj.rs / e2e_shbond.rs 集成测试
│  ├─ simx-server/      # 独立后端：WebSocket 控制接口
│  └─ simx-update-server/  # 升级服务器：网页上传安装包 + 自动生成 version.json（crates/ 下）
├─ src-tauri/           # Tauri 桌面壳（main.rs + tauri.conf.json + 图标）
├─ src/                 # 前端源码（App.vue、components/、types.ts、backend.ts、changelog.ts、updater.ts）
├─ docs/                # 文档（协议 PDF、本手册等）
├─ scripts/             # 辅助脚本（build-all.ps1 打包前准备、图标生成、smoke 测试等）
├─ simx.config.json     # 运行时配置：local（内嵌引擎）/ remote（远程后端）
└─ Cargo.toml           # Cargo workspace 根
```

## 2. 环境准备（Windows 开发机）

| 工具 | 安装方式 | 验证命令 |
| --- | --- | --- |
| Visual Studio C++ 生成工具 | VS Installer 勾选「使用 C++ 的桌面开发」 | — |
| Rust（MSVC 工具链） | `winget install Rustlang.Rustup` | `cargo --version` |
| Node.js ≥ 18 | 官网安装包或 winget | `node --version` |
| WebView2 运行时 | Win10/11 一般自带 | — |

⚠️ **注意点**：
- Rust 必须在 VS C++ 生成工具**之后**安装（rustup 依赖 MSVC 链接器）。
- 安装 rustup 后**新开一个终端**再验证，PATH 是安装器写入的，旧终端里找不到 `cargo`。
- 若脚本环境中仍找不到 cargo，可临时补 PATH：
  ```powershell
  $env:Path = "$env:USERPROFILE\.cargo\bin;$env:Path"
  ```
- 本项目终端命令均按 **PowerShell** 编写。老版本 PowerShell **不支持 `&&`
  连接命令**，多条命令请用分号 `;` 分隔。

首次拉取代码后安装前端依赖（仅需一次）：

```powershell
npm install
```

## 3. 开发模式调试（热更新）

```powershell
npm run tauri dev
```

该命令会自动做两件事并保持监听：
1. 启动 Vite 前端开发服务器（`http://127.0.0.1:14200`），改前端代码即时热更新；
2. `cargo run` 编译并启动 Tauri 桌面窗口，改 Rust 代码保存后自动重新编译。

⚠️ **注意点**：
- **首次编译很慢**（需编译几百个 Rust 依赖，约几分钟），后续增量编译很快。
- **前端端口固定为 14200**，配置位于两处，必须保持一致：
  - `vite.config.ts` → `server.port: 14200`
  - `src-tauri/tauri.conf.json` → `"devUrl": "http://127.0.0.1:14200"`
- **不要把端口改回 1420 附近**！Windows 将 1381–1480 端口段保留给
  Hyper-V/WSL，监听会报 `listen EACCES: permission denied`（详见第 8 节坑 ①）。

### 只调试前端（可选）

```powershell
npm run dev
```

纯浏览器打开 `http://127.0.0.1:14200`。此时不在 Tauri 环境中，前端会按
`simx.config.json` 的 `remote` 配置尝试连 WebSocket 后端——适合搭配
`simx-server` 调试远程模式；不启动后端则界面显示"连接中"。

前端构建检查：

```powershell
npx vite build            # 打包产物验证
node .\node_modules\typescript\bin\tsc --noEmit   # 纯类型检查（用项目本地 tsc，避开 npx 缓存版本）
```

## 5. 构建发布版（桌面端）

> 本项目选定 **NSIS 安装包（.exe）** 作为正式分发方案：
> Tauri 内置 bundler 直接产出，包体小、中文界面支持好，
> 默认"仅当前用户安装"不需要管理员权限。
> 若将来需要企业 IT 静默批量部署，再把 `tauri.conf.json` 的
> `bundle.targets` 改为 `["nsis", "msi"]` 即可同时产出 MSI。

### 5.1 一键打包（推荐）

```powershell
npm run tauri build
```

该命令自动执行三步：`beforeBuildCommand`（scripts/build-all.ps1：准备 Linux 后端产物
+ 构建前端 dist）→ `cargo build --release` → NSIS 打包。产物：

| 产物 | 路径 |
| --- | --- |
| 免安装 exe | `target\release\simuxchange.exe` |
| NSIS 安装包 | `target\release\bundle\nsis\SimuXchange_1.0.0_x64-setup.exe` |

**Linux 后端自动打包**：安装包内嵌 `target\x86_64-unknown-linux-musl\release\simx-server`
与 `scripts/start.sh` / `scripts/stop.sh`（`tauri.conf.json` 的 `bundle.resources`
映射为 `Linux/simx-server` / `Linux/start.sh` / `Linux/stop.sh`），
安装后位于**安装目录的 `Linux\` 目录**，整个目录拷到 Linux 服务器即可部署
（musl 静态链接，任意发行版可跑，见 6.2 节）。build-all.ps1 **每次打包都会跑
`cargo build` 做增量判断**：服务端代码有改动时自动重新编译（不会出现"Linux 产物
还在就打包进旧版"），代码没变则接近秒过、不重复链接。链接方式自动探测：机器上
装有 musl 交叉工具链（`x86_64-linux-musl-gcc` / `musl-gcc`）时用常规链接，否则
直接用 **rust-lld 自包含链接**（Rust 自带链接器，rustc 1.82+ 无需额外安装，也
不会先报错再重试）；探测结果记录在 `target\x86_64-unknown-linux-musl\.linker-mode`
供后续打包沿用，编译仍失败才中止打包并提示。

⚠️ **NSIS 安装包分发注意点**：
- **SmartScreen 提示**：未购买代码签名证书的安装包，用户首次运行时
  Windows 可能弹"未知发布者"警告，点"仍要运行"即可，属正常现象；
  仅内部/个人使用不必购买证书。
- **WebView2 运行时**：目标机器缺少 WebView2 时，安装器会自动引导下载，
  无需手动处理（Win10/11 一般自带）。
- **升级方式**：新版本直接覆盖安装即可，网关配置 `gateways.json`
  保存在安装目录（exe 同目录），覆盖安装不会删除它；但**卸载会清空
  安装目录**，卸载前如需保留配置请先备份该文件。发布前记得同步更新
  `tauri.conf.json` 和 `package.json` 里的版本号（安装包文件名中的
  1.0.0 来自这里）。

### 5.2 手动分步构建（理解原理 / 排查问题时用）

```powershell
npx vite build                              # ① 生成 dist/ 前端资源
cargo build --release -p simuxchange       # ② 编译 Rust 主程序（嵌入 dist）
```

⚠️ **关键注意点（曾导致发布版白屏）**：
`src-tauri/Cargo.toml` 中必须保留以下配置——

```toml
[features]
default = ["custom-protocol"]
custom-protocol = ["tauri/custom-protocol"]
```

`custom-protocol` 特性的作用是**把 dist 前端资源嵌进 exe**。若缺少
`default = ["custom-protocol"]`，`cargo build --release` 出来的 exe
会去加载开发地址 `http://127.0.0.1:14200`，表现为启动后**「localhost 拒绝连接」**。
（dev 模式不受影响：Tauri CLI 以 `--no-default-features` 运行并加载 devUrl。）

### 5.3 发布版部署文件布局

```
任意目录/
├─ simuxchange.exe      # 主程序
├─ simx.config.json     # 运行配置（local/remote + 可选 updateUrl），与 exe 同目录
├─ Linux/               # 安装包自带的 Linux 后端（musl 静态编译，拷到服务器即可用）
│   ├─ simx-server
│   ├─ start.sh         # crontab 定时启停脚本（见 6.3 节）
│   └─ stop.sh
├─ gateways.json     # 网关配置（程序自动生成/维护）
├─ packets/          # 收发报文日志（平台开启“展示收发报文”时自动生成）
│   └─ 20260814/                # 按日期分文件夹（YYYYMMDD）
│       └─ 分组7深圳模拟撮合1_现货集中竞价交易平台/   # 日期下按“网关名_平台名”分文件夹
│           └─ pkg_203526_ip-192_168_1_100_port-8080.log   # 每条连接一个文件
└─ log/              # 前端操作日志（带前端 IP，自动生成）
    └─ 20260816/                # 按日期分文件夹（YYYYMMDD）
        └─ ops.log              # 当天全部操作日志
```

文件名格式：`pkg_<接入时分秒>_ip-<客户端IP点转下划线>_port-<客户端端口>.log`（
连接号不体现在文件名里，对端 IP:端口与接入时间即可唯一定位一条连接；
断开后文件保留，重连产生的报文写进新文件）。

报文文件内容与界面弹窗展示一致，每条报文两行：
`时:分:秒.毫秒 RECV/SEND  大写十六进制字节`（RECV=收，SEND=发）下方紧跟
按交易所字段名解析的缩进续行（`字段名: 值`），逐行 flush 写入。

程序按「exe 同目录 → 开发目录（target/debug 上溯）」的顺序查找数据目录，
所以**部署时把 `simx.config.json` 和 exe 放在一起**即可。

## 6. 构建独立后端 simx-server（远程部署）

### 6.1 构建

Windows 本机构建：

```powershell
cargo build --release -p simx-server
```

产物 `target\release\simx-server.exe`，临时运行：

```powershell
.\simx-server.exe --listen 0.0.0.0:9800
```

- `--listen`：WebSocket 控制接口监听地址（前端连 `ws://IP:9800/ws`）
- **数据目录**：固定为程序（exe）所在目录，网关配置与启停状态（`gateways.json`，
  每个网关的 `wasRunning` 字段记录“上次是否在运行”）、报文文件 `packets/`、
  前端操作日志 `log/` 都在这里（与桌面端“配置放 exe 旁边”的约定一致），整个目录拷走即可迁移；
  开发模式下 exe 在 `target/debug/`，数据会落在那里（正常现象）
- `--auto-start`：**可选**。启动完成后自动恢复**上次运行中**的网关（引擎把网关启停
  状态记在 `gateways.json` 的 `wasRunning` 字段，只启动上次退出时仍在运行的网关）；
  不加则保持原有行为，所有网关都不自动启动，由界面手动启动
- `--update-url`：**可选**。启动时向更新服务器（`<地址>/version.json`）检查一次
  新版本并打印提示（只提示不自动替换，适合定时启停的无人值守场景自查版本），
  服务器不可达或清单无效时静默忽略，不影响启动

### 6.2 Linux 部署（推荐：用户目录 + crontab 定时启停）

simx-server 是**单文件静态程序**：Windows 打包时自动生成 musl 静态编译产物
（见 5.1 节），不依赖任何系统库，拷到任意 Linux 发行版即可运行，
**无需在服务器上安装 Rust/编译环境**。部署在**用户目录**下，无需 root：

**① 获取程序**——从 Windows 打包产物直接拷贝（二选一）：

- 安装包安装后：安装目录的 `Linux\` **整个目录**（含 `simx-server`、`start.sh`、`stop.sh`）
- 打包前的源产物：`target\x86_64-unknown-linux-musl\release\simx-server`
  + `scripts/start.sh` + `scripts/stop.sh`

```bash
# 1. 上传到服务器并安装到用户目录：~/simx-server/
#    安装包里的 Linux\ 目录三个文件一起拷，脚本和可执行文件必须同目录
mkdir -p ~/simx-server
cp simx-server start.sh stop.sh ~/simx-server/
chmod +x ~/simx-server/simx-server ~/simx-server/start.sh ~/simx-server/stop.sh
```

> 数据目录 = **exe 所在目录**（即 `~/simx-server/`）：网关配置与启停状态
> （`gateways.json` 的 `wasRunning` 字段）、报文文件 `packets/`、日志都在
> 这一个目录下，无需另行准备数据目录。

> 产物为 **musl 静态链接**，不依赖目标机的 glibc 版本（`file simx-server`
> 显示 `statically linked`），Ubuntu/CentOS 等发行版均可直接运行。
> 如需自行编译（如改了服务端代码），在任意装了 Rust 的 Linux 机器上
> `cargo build --release -p simx-server` 即可，仅需 build-essential + rustup。

```bash
# 手动试运行（前台，Ctrl+C 退出）；加 --auto-start 可启动后自动恢复上次运行中的网关
~/simx-server/simx-server --listen 0.0.0.0:9800 [--auto-start]
```

### 6.3 crontab 定时启停（推荐）

用 `start.sh` 与 `stop.sh`（随安装包 `Linux\` 目录一起提供）配进当前用户的 crontab，
**每天定时启动/停止后端**（如早 8 点开、晚 10 点关），无需 root、
无需 systemd。盘中进程异常退出不会自动拉起（本方案不做保活）：

```bash
# 1. 脚本已在 ~/simx-server/（与 simx-server 同目录）并已加执行权限（见 6.2 ①）
# 2. 编辑当前用户的定时任务（把 user 换成实际用户名）
crontab -e
# 加入下面两行后保存（每天 08:00 启动、22:00 停止）：
0 8 * * *  /home/user/simx-server/start.sh
0 22 * * * /home/user/simx-server/stop.sh

# 3. 确认已生效
crontab -l
```

也可手动执行 `~/simx-server/start.sh` / `~/simx-server/stop.sh` 随时启停
（start.sh 已在运行时直接跳过，不会重复启动导致端口冲突；
stop.sh 收尾会顺带清理 `log/` 与 `packets/` 下 **7 天前**按日期归档的文件夹，
长期运行不会堆积旧日志）。

常用运维命令：

```bash
tail -f ~/simx-server/server.log   # 实时滚动后端日志
```

若启用了防火墙（ufw）：`sudo ufw allow 9800/tcp`。

> 说明：start/stop 脚本与 systemd 是两种实现同样目的的方式——
> systemd 需要 root 且随系统服务管理；crontab 定时启停完全在用户目录下，
> 适合无 root 权限的个人服务器。

### 6.4 前端切换远程后端

桌面端右上角徽章（本地引擎/远程后端）**本身就是切换入口**：点击后可在弹窗里
**配置多个后端**（本地引擎为固定项，远程可添加/删除多个），点选即切换，
立即生效并写入 `simx.config.json`（下次启动自动生效），无需手改配置文件。
等效的手工配置方式：

```json
{
    "backend": "b-srv1",
    "remoteUrl": "ws://<服务器IP>:9800/ws",
    "backends": [
        { "id": "local", "name": "本地引擎", "kind": "local", "url": "" },
        { "id": "b-srv1", "name": "测试机房", "kind": "remote", "url": "ws://<服务器IP>:9800/ws" }
    ]
}
```

`backend` 字段存当前选中的后端 id；旧版配置文件（只有 backend/remoteUrl）
仍可正常使用，程序会自动把“远程”合成为一个列表项。

### 6.5 部署后验证

1. 服务器上执行 `~/simx-server/start.sh`，`pgrep -f "simx-server --listen"` 能查到进程
2. 本机浏览器访问 `http://<服务器IP>:9800/health` 返回 `ok`
3. 桌面端点击右上角徽章，在弹窗里添加远程后端填地址，点选后右上角显示
   「<名称>·已连接」即成功；断线后界面每 2 秒自动重连

### 6.6 搭建更新服务器（自动升级）

更新服务器只需提供一个 HTTP 可访问的目录（`version.json` + 安装包）即可。
**推荐用项目自带的升级服务器程序 `simx-update-server`**（网页上传、自动生成清单），
也可直接用任意静态目录（零程序，见方式二）。

**方式一（推荐）：simx-update-server 升级服务器**

单文件程序（axum，无外部依赖），Windows/Linux 均可运行；构建：

```powershell
cargo build --release -p simx-update-server                         # Windows
cargo build --release -p simx-update-server --target x86_64-unknown-linux-musl   # Linux（musl 静态，可拷到任意发行版）
```

部署运行（Linux 服务器为例）：

```bash
mkdir -p ~/simx-update && cp simx-update-server ~/simx-update/
~/simx-update/simx-update-server --listen 0.0.0.0:8080 --dir ~/simx-update
```

使用：浏览器打开 `http://<服务器IP>:8080` 即管理页面——上传安装包
（文件名须含版本号，如 `SimuXchange_1.1.0_x64-setup.exe`）、可选 Linux 后端
`simx-server`、更新说明，程序自动生成 `version.json` 并对外提供下载。
桌面端「更新服务器地址」填 `http://<服务器IP>:8080`；
simx-server 启动加 `--update-url http://<服务器IP>:8080` 即可自查版本。

实现要点（维护用）：版本号从安装包文件名自动解析，**版本号最大的**作为当前版
（1.10.0 > 1.9.0）；更新说明按版本号存 `notes.json`，上传时填写；手工拷入目录的
文件也会被自动扫描进清单（无说明则 notes 为空数组）；删除文件/无安装包时
`version.json` 返回 404，客户端静默忽略。

**方式二：任意静态目录（零程序）**

1. `npm run tauri build` 产出安装包（自动含 Linux 后端，见 5.1 节）；
2. 把安装包（和可选的新版 Linux `simx-server`）拷到服务器更新目录；
3. 编写/更新该目录下的 `version.json`：

```json
{
    "version": "1.1.0",
    "notes": ["新增 XX 功能", "修复 XX 问题"],
    "winInstaller": "SimuXchange_1.1.0_x64-setup.exe",
    "linuxServer": "simx-server"
}
```

目录本身用任意静态文件服务暴露（如 Linux 的 `python3 -m http.server 8080`
或 nginx 静态站点；Windows 的 IIS），客户端配置同上。

两种方式下：桌面端启动 3 秒后自动检查，发现 `version` 比当前大则弹窗，点「下载并安装」
把安装包下载到本机 Downloads 并启动安装程序（覆盖安装，配置不丢）；
后端自查：启动 simx-server 时加 `--update-url`，启动日志打印“发现新版本 / 已是最新版本”。

`version` 用“数字点分”比较（如 1.1.0 > 1.0.9）；版本号更新在 `tauri.conf.json`
与 `package.json`（安装包文件名）以及 `src/changelog.ts`（界面“ⓘ 关于”里的更新说明）。

## 8. 踩坑记录（重要！）

### ① Vite 启动报 `listen EACCES: permission denied 127.0.0.1:1420`

**不是权限问题。** Windows 将 1381–1480 端口段保留给 Hyper-V/WSL，查看保留段：

```powershell
netsh interface ipv4 show excludedportrange protocol=tcp
```

Vite 默认端口 1420 恰好落在保留段内。本项目已改用 **14200**；
若再遇到，选保留段之外的端口，并**同步修改两处**：
`vite.config.ts` 的 `server.port` 和 `tauri.conf.json` 的 `devUrl`。

### ② 发布版 exe 启动显示「localhost 拒绝连接」/ 白屏

`custom-protocol` 特性未启用，前端资源没有嵌入 exe。确认
`src-tauri/Cargo.toml` 的 `[features]` 下有 `default = ["custom-protocol"]`
（见 5.2 节），然后重新 `cargo build --release -p simuxchange`。

### ③ 新终端找不到 `cargo` 命令

rustup 安装器已写入 PATH，但只对**之后新开的终端**生效。重开终端，或临时执行：

```powershell
$env:Path = "$env:USERPROFILE\.cargo\bin;$env:Path"
```

### ④ cargo 编译报「拒绝访问 (os error 5)」

多发生在 `build-script-build` 阶段，是杀毒软件/系统对临时生成的构建脚本
exe 的拦截，**并非代码问题**。重跑一次构建命令通常即可通过；
反复出现时把项目目录和 `target\` 加入杀毒软件白名单。

### ⑤ PowerShell 里命令连不起来

老版本 PowerShell 不支持 `&&`，用分号：

```powershell
npx vite build; cargo build --release -p simuxchange
```

### ⑥ cargo 显示 ExitCode 1 但其实编译成功

PowerShell 把 cargo 的进度条输出当 stderr 处理，某些终端封装据此误判失败。
**以输出末尾的 `Finished`（编译）/ `test result: ok`（测试）为准。**

### ⑦ 修改了后端 Rust 结构体，前端类型报错

前后端类型是手工对应的：Rust 结构体（serde 序列化为 camelCase）↔
`src/types.ts` 的 interface。改任何一边都要**同步改另一边**。

### ⑧ 打包时报 `failed to bundle project: timeout: global`（NSIS 下载超时）
`npm run tauri build` 首次打包需从 GitHub 下载 NSIS 工具链，
网络不通 GitHub 时会卡在 `Downloading … nsis-3.11.zip` 这一步直到超时
（此时 Rust 编译其实已成功）。解决办法：手动把工具链放进 Tauri 的
缓存目录 `%LOCALAPPDATA%\tauri\NSIS`，之后打包会跳过下载。

1. 经镜像下载两个文件（镜像前缀如 `https://ghfast.top/` + 原 GitHub 地址）：
   - `https://github.com/tauri-apps/binary-releases/releases/download/nsis-3.11/nsis-3.11.zip`
   - `https://github.com/tauri-apps/nsis-tauri-utils/releases/download/nsis_tauri_utils-v0.5.3/nsis_tauri_utils.dll`
2. **校验完整性**（SHA1 必须与 Tauri 官方源码记录的一致，防镜像篡改）：
   ```powershell
   Get-FileHash $env:TEMP\nsis-3.11.zip -Algorithm SHA1          # 应为 EF7FF767E5CBD9EDD22ADD3A32C9B8F4500BB10D
   Get-FileHash $env:TEMP\nsis_tauri_utils.dll -Algorithm SHA1   # 应为 75197FEE3C6A814FE035788D1C34EAD39349B860
   ```
   （校验值对应 Tauri CLI 2.11.4 / NSIS 3.11；升级 CLI 后以 tauri 源码
   `crates/tauri-bundler/src/bundle/windows/nsis/mod.rs` 里的常量为准）
3. 解压到缓存目录并摆好插件：
   ```powershell
   Expand-Archive $env:TEMP\nsis-3.11.zip -DestinationPath $env:LOCALAPPDATA\tauri -Force
   Rename-Item $env:LOCALAPPDATA\tauri\nsis-3.11 'NSIS'
   New-Item -ItemType Directory -Force -Path $env:LOCALAPPDATA\tauri\NSIS\Plugins\x86-unicode\additional
   Copy-Item $env:TEMP\nsis_tauri_utils.dll $env:LOCALAPPDATA\tauri\NSIS\Plugins\x86-unicode\additional\
   ```
   （若 Rename-Item 报"拒绝访问"，是杀毒软件正在扫描新解压的文件，等几秒重试）
4. 重新 `npm run tauri build`，会直接进入 `Running makensis` 打包阶段。

### ⑨ cargo 拉取依赖报 `spurious network error ... 404`

本机全局 `~/.cargo/config.toml` 默认走 tuna（git 镜像），网络波动时经常 404。
解决办法：在**项目根建 `.cargo/config.toml`** 覆盖为 aliyun sparse 镜像
（文件方式最可靠，命令行 `--config` 在 PowerShell 里引号易被吃掉）：

```toml
[source.crates-io]
registry = "https://github.com/rust-lang/crates.io-index"
replace-with = "aliyun"

[source.aliyun]
registry = "sparse+https://mirrors.aliyun.com/crates.io-index/"

[http]
check-revoke = false
```

删除该文件即恢复全局配置。aliyun 连通性自查：
`curl.exe -s -o NUL -w "%{http_code}" https://mirrors.aliyun.com/crates.io-index/config.json`
返回 200 即正常（注意 PowerShell 里 `curl` 是 Invoke-WebRequest 别名，要用 `curl.exe`）。

### ⑩ PowerShell 脚本中文变乱码、报“字符串缺少终止符”

Windows PowerShell 5.1 对 **UTF-8 无 BOM** 的 .ps1 按 ANSI（GBK）读取，
中文注释/字符串会乱码并引发解析错误。**新建含中文的 .ps1 必须保存为 UTF-8 with BOM**
（编辑器的“带 BOM 的 UTF-8”；或转换：
`$c = Get-Content -Raw -Encoding UTF8 a.ps1; [IO.File]::WriteAllText((Resolve-Path a.ps1), $c, (New-Object Text.UTF8Encoding $true))`）。
`scripts/build-all.ps1` 由 tauri 的 beforeBuildCommand 调用，踩过此坑。
