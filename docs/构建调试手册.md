# SimuXchange 构建调试手册

> 本手册面向需要**从源码手动编译、调试、打包**本项目的开发者。
> 按顺序照做即可完成从零环境到发布产物的全过程；文末汇总了实际开发中踩过的所有坑。

---

## 1. 项目概览

SimuXchange 是跨平台模拟撮合软件：模拟交易所交易网关（TGW），接受柜台（OMS）的
Binary 协议 TCP 连接（上海综合网关则通过 SQL Server 接口表交换 STEP 消息），
按配置策略回送确认/成交回报。支持四类网关（新建时选择分类）：
**深圳统一网关**（深交所 Binary，sz）、**上海竞价网关**（上交所竞价平台 Binary 0.54，shjj）、
**上海新债券网关**（上交所债券平台 Binary 1.90，shbond）与
**上海综合网关**（上交所综合业务平台 EzSTEP 数据库接口，shzh）。
三套 Binary 协议按后缀分文件存放（`*_sz.rs` / `*_shjj.rs` / `*_shbond.rs`），
上海综合网关在 `crates/simx-core/src/shzh/`（protocol/db/session/strategy）。技术栈：

| 层 | 技术 | 说明 |
| --- | --- | --- |
| 核心引擎 | Rust（tokio 异步） | `crates/simx-core`，协议编解码 + 会话 + 回报策略 |
| 桌面壳 | Tauri 2 | `src-tauri/`，内嵌引擎，包名 `simuxchange` |
| 独立后端 | Rust + axum WebSocket | `crates/simx-server`，服务器远程部署用 |
| 前端界面 | Vue 3 + TypeScript + Vite 6 | `src/` |

```
SimuXchange/
├─ crates/
│  ├─ simx-core/        # 核心库（协议、会话、策略、统计、报文捕获）
│  │   ├─ src/sz/       # 深圳统一网关：protocol.rs / session.rs / strategy.rs
│  │   ├─ src/shjj/     # 上海竞价网关：protocol.rs / session.rs / strategy.rs
│  │   ├─ src/shbond/   # 上海新债券网关：protocol.rs / session.rs / strategy.rs
│  │   ├─ src/shzh/     # 上海综合网关：protocol.rs / db.rs / session.rs / strategy.rs
│  │   └─ tests/        # e2e_sz.rs / e2e_shjj.rs / e2e_shbond.rs 集成测试
│  ├─ simx-server/      # 独立后端：WebSocket 控制接口
│  └─ simx-update-server/  # 升级服务器：自动扫描发布目录 + 生成 version.json（crates/ 下）
├─ src-tauri/           # Tauri 桌面壳（main.rs + tauri.conf.json + 图标）
├─ src/                 # 前端源码（App.vue、components/、types.ts、backend.ts、changelog.ts、updater.ts）
├─ docs/                # 文档（协议 PDF、本手册等）
├─ scripts/             # 辅助脚本（build-all.ps1 打包前准备、图标生成、smoke 测试等）
├─ simx.config.json     # 运行时配置：local（内嵌引擎）/ remote（远程后端）+ llm（模型接口）
└─ Cargo.toml           # Cargo workspace 根
```

## 2. 环境准备（Windows 开发机）

| 工具 | 安装方式 | 验证命令 |
| --- | --- | --- |
| Visual Studio C++ 生成工具 | VS Installer 勾选「使用 C++ 的桌面开发」 | — |
| Rust（MSVC 工具链） | `winget install Rustlang.Rustup` | `cargo --version` |
| Node.js ≥ 18 | 官网安装包或 winget | `node --version` |
| WebView2 运行时 | Win10/11 一般自带 | — |
| zig | 仅**打包发布版**需要（`npm run tauri build`）：① 下载 <https://ziglang.org/download/> 的 Windows x86_64 版（约 50MB，单 zip）；② 解压到如 `C:\zig`（推荐，脚本会自动探测）；③ 建议把解压目录加入系统 PATH（不加也行，脚本探测 `C:\zig\zig-*\zig.exe`） | `zig version` |
| Oracle Instant Client | 仅使用「同步持仓数据」（Oracle 查询）功能时需要，**运行期依赖**：Windows 安装 64 位 Instant Client 后通常自动可用；Linux 需解压 Instant Client 并通过 `start.sh` 的 `ORACLE_CLIENT_DIR` 加入 `LD_LIBRARY_PATH`。**只有 glibc 版 simx-server 能加载**（随包的 musl 静态版不支持） | 查询持仓按钮能连上数据库 |

⚠️ **注意点**：
- Rust 必须在 VS C++ 生成工具**之后**安装（rustup 依赖 MSVC 链接器）。
- 安装 rustup 后**新开一个终端**再验证，PATH 是安装器写入的，旧终端里找不到 `cargo`。
- 若脚本环境中仍找不到 cargo，可临时补 PATH：
  ```powershell
  $env:Path = "$env:USERPROFILE\.cargo\bin;$env:Path"
  ```
- 本项目终端命令均按 **PowerShell** 编写。老版本 PowerShell **不支持 `&&`
  连接命令**，多条命令请用分号 `;` 分隔。
- **zig 为什么是必装项**：引入「Lua 脚本回报」功能（1.1.0）后，依赖里包含
  mlua 的 **vendored Lua C 源码**，Linux 后端 musl 交叉编译时要先用交叉 C 编译器
  把 Lua 编译成 musl 目标文件。build-all.ps1 探测顺序：musl 交叉 gcc
  （`x86_64-linux-musl-gcc` / `musl-gcc`）→ zig（`zig cc -target x86_64-linux-musl`
  充当交叉编译器），都找不到会直接中止打包并提示本节安装方法。
  **注意：musl.cc 上发布的工具链是 Linux 宿主版**（二进制是 ELF，Windows 上
  无法运行），Windows 打包机请用 zig。只做日常开发（`cargo test` /
  `npm run tauri dev`）不需要它（Windows 本机编译用的是 MSVC 自带的 cl.exe）。
- **Oracle 驱动（oracle / odpic-sys）**：包含 ODPI-C 的 C 源码，Linux musl
  交叉编译同样走上面的交叉 C 编译器（zig cc），不需要 Oracle 客户端才能编译；
  Oracle Instant Client 只是**运行期**动态加载（见上表）。注意 Linux 版默认是
  musl 静态链接，**无法加载 glibc 版 Oracle Instant Client**；「同步持仓数据」
  建议在 Windows 桌面端使用。如确需在 Linux 服务端使用：
  - Windows 打包机交叉编译 glibc 版（zig，默认 glibc 2.17 基线，CentOS 7+ 可运行）：

    ```powershell
    .\scripts\build-glibc-server.ps1                        # 产物 dist\linux-glibc\simx-server-glibc
    .\scripts\build-glibc-server.ps1 -GlibcVersion 2.28     # 按目标服务器 glibc 调整下限
    ```

    上传覆盖服务器 `~/simx-server/simx-server`，`start.sh` 的 `ORACLE_CLIENT_DIR`
    会把它加入 `LD_LIBRARY_PATH`；
  - 或在**与目标机 glibc 版本一致**的 Linux 环境执行
    `cargo build --release -p simx-server`（不带 `--target`，链接宿主 glibc）后替换。

  发布包（7z）的 `Linux\simx-server\` 里两个版本都会附带；

首次拉取代码后安装前端依赖（仅需一次）：

```powershell
npm install
```

## 3. 开发模式调试（热更新）

```powershell
npm run tauri dev
```

该命令会自动做两件事并保持监听：
1. 启动 Vite 前端开发服务器（`http://127.0.0.1:14200`），改前端代码即时热更新；
2. `cargo run` 编译并启动 Tauri 桌面窗口，改 Rust 代码保存后自动重新编译。

⚠️ **注意点**：
- **首次编译很慢**（需编译几百个 Rust 依赖，约几分钟），后续增量编译很快。
- **前端端口固定为 14200**，配置位于两处，必须保持一致：
  - `vite.config.ts` → `server.port: 14200`
  - `src-tauri/tauri.conf.json` → `"devUrl": "http://127.0.0.1:14200"`
- **不要把端口改回 1420 附近**！Windows 将 1381–1480 端口段保留给
  Hyper-V/WSL，监听会报 `listen EACCES: permission denied`（详见第 8 节坑 ①）。

### 只调试前端（可选）

```powershell
npm run dev
```

纯浏览器打开 `http://127.0.0.1:14200`。此时不在 Tauri 环境中，前端会按
`simx.config.json` 的 `remote` 配置尝试连 WebSocket 后端——适合搭配
`simx-server` 调试远程模式；不启动后端则界面显示"连接中"。

## 4. 测试与编译检查

```powershell
# 快速语法/类型检查（不生成可执行文件，最快）
cargo check -p simx-core -p simx-server

# 核心库全部测试：148 个单元测试（含订单缓存、报文捕获/重发缓存、操作日志、三/四套协议字段解析、STEP 编解码、深/沪 PCF 清单解析与缓存、ETF 持仓扣减）+ 4 个自动启动 + 3 个综合配置集成测试 + 30 个 TCP 端到端集成测试（深交所 17 + 上交所竞价 7 + 上交所新债券 6）+ 2 个上海综合数据库 e2e（基础流程 + ETF PCF，需环境变量，见下）
cargo test -p simx-core
```

端到端测试（`crates/simx-core/tests/e2e_sz.rs`、`e2e_shjj.rs` 与 `e2e_shbond.rs`）会真实启动引擎、用 TCP 连接
127.0.0.1 的 18101~18116（深交所）、18201~18206（上交所竞价）与 18301~18305（上交所新债券）端口完成 Logon → 委托 → 回报校验（含回报同步按 begin 重发历史回报、操作日志落盘、ETF 申赎按 PCF 清单文件回成份股明细、ETF 申购按同步持仓扣减/现金替代/拒单）。

上海综合网关的数据库端到端测试（`tests/e2e_shzh_db.rs`）需要真实 SQL Server；未设置环境变量时自动跳过。
测试会建两张唯一命名的临时表（`simx_req_*` / `simx_exec_*`）并在结束时删除，账号需有建表/删表权限：

```powershell
$env:SIMX_TEST_MSSQL_HOST="127.0.0.1"
$env:SIMX_TEST_MSSQL_PORT="1433"
$env:SIMX_TEST_MSSQL_DB="ezstep_test"
$env:SIMX_TEST_MSSQL_USER="sa"
$env:SIMX_TEST_MSSQL_PASSWORD="******"
cargo test -p simx-core --test e2e_shzh_db -- --nocapture
```

> SQL Server 需启用 TCP/IP 与 SQL Server 身份验证。测试覆盖：启动平台 → 写入 STEP 新委托 →
> 确认回写 reqresp → 成交插入 execreport（校验 bcasttype/setid/价格/数量）→ 终态撤单回
> OrderCancelReject(9)；另含 ETF PCF 用例：EEC 现金申购（类型1+类型3）与 IEC 实物申购
> （类型1+类型2 成份券+类型3 资金替代，校验现金替代金额与市场分组）。

订单缓存、按状态撤单与手动回复的端到端冒烟（需先启动 simx-server，脚本自动建/复用网关，测完自动恢复原策略）：


前端构建检查：

```powershell
npx vite build            # 打包产物验证
node .\node_modules\typescript\bin\tsc --noEmit   # 纯类型检查（用项目本地 tsc，避开 npx 缓存版本）
```

**SQL Server 驱动版本**：上海综合网关使用 `tiberius 0.12.x`（功能对应 tds73 + rustls 0.21 + ring），
Windows 与 Linux musl 交叉编译都不需要额外系统库。**不要随手升级到 0.13**——0.13 的 rustls
链路会引入 aws-lc-rs，交叉编译需要 CMake/NASM，显著增加打包复杂度。

⚠️ **注意点**：
- PowerShell 会把 cargo 的进度输出当作 stderr，导致某些封装环境下显示
  ExitCode 非 0——**以输出末尾是否出现 `Finished` / `test result: ok` 判断成功**。
- 若 cargo 编译报「拒绝访问 (os error 5)」且指向 `build-script-build`，
  多为杀毒软件/权限拦截了构建脚本，**重跑一次**通常即恢复（见第 8 节坑 ④）。

## 5. 构建发布版（桌面端）

> 本项目**不发安装包，只发布绿色版 7z 包**：`scripts\pack-all.ps1` 生成
> `dist\SimuXchange_V<版本号>.7z`，用户解压即可运行、随发布目录自动升级
> （见 6.6 节），无需安装程序。

### 5.1 一键打包（推荐）

```powershell
.\scripts\pack-all.ps1
```

该命令自动执行：

1. `npm run tauri build -- --no-bundle`（`beforeBuildCommand` 即 build-all.ps1：
   交叉编译 Linux musl 三件套 + Windows CLI + 构建前端，再编译桌面端；
   `bundle.active=false`，**不生成 NSIS 安装包**）；
2. `build-glibc-server.ps1` 额外交叉编译 glibc 版 `simx-server`（Oracle 查询用）；
3. 按固定布局汇总到 `dist\pkg\SimuXchange\`，用 7z 压缩为 `dist\SimuXchange_V<版本号>.7z`。

发布包内部布局（`Linux\` 下每个工具独立目录）：

```
SimuXchange\
├─ simuxchange.exe
├─ simx-cli.exe
├─ simx.config.json
├─ docs\                （CLI工具使用手册 / Lua脚本回报编写说明 / 产品使用手册 / 项目简介）
└─ Linux\
   ├─ simx-cli\simx-cli
   ├─ simx-server\
   │  ├─ simx-server-musl    默认，静态链接，任何 x86_64 Linux 可用
   │  ├─ simx-server-glibc   需要 Oracle 查询时用，要求 glibc >= 2.17
   │  └─ start.sh / stop.sh  （./start.sh [musl|glibc] 选择，默认 musl）
   └─ simx-update-server\{simx-update-server,start-update.sh,stop-update.sh}
```

版本号取自 `src-tauri\tauri.conf.json`，脚本只读取、不会自动升版本。
`simx-server-musl` 为 musl 静态链接（任意 x86_64 发行版可跑）；
`simx-server-glibc` 为动态链接（Oracle 查询用，需 glibc ≥ 2.17）。
`Linux\` 下每个工具独立目录，拷贝后 `chmod +x` 即可部署（见 6.2 / 6.6 节）。
build-all.ps1 每次打包都会跑 `cargo build` 做增量判断：服务端代码有改动时自动重新编译
（不会出现"Linux 产物还在就打包进旧版"），代码没变则接近秒过、不重复链接。
**C 交叉编译器**（1.1.0 起，mlua 的 vendored Lua C 源码必需）：打包前探测
`x86_64-linux-musl-gcc` / `musl-gcc`，找到后自动设置 `CC_x86_64_unknown_linux_musl` /
`AR_x86_64_unknown_linux_musl` 环境变量供 cc crate 使用；找不到则中止打包并提示
安装方法（见第 2 节）。链接方式：默认 **rust-lld 自包含链接**（Rust 自带链接器，
rustc 1.82+ 无需额外安装，musl-gcc 编出的 C 目标文件可直接参与链接）；探测结果
记录在 `target\x86_64-unknown-linux-musl\.linker-mode` 供后续打包沿用，
编译仍失败才中止打包并提示。

⚠️ **绿色版分发注意点**：
- **SmartScreen 提示**：未购买代码签名证书的 exe，用户首次运行时
  Windows 可能弹"未知发布者"警告，点"仍要运行"即可，属正常现象；
  仅内部/个人使用不必购买证书。
- **WebView2 运行时**：目标机器缺少 WebView2 时，界面无法显示
  （程序仍可运行），需先安装 WebView2 运行时（Win10/11 一般自带）。
- **升级方式**：走自动升级（见 6.6 节）自动覆盖目录内发布文件，配置
  `gateways.json` 保存在 exe 同目录、不在升级清单里不会被碰；如需手动
  换版本，直接解压新版覆盖旧目录即可（覆盖安装不会删 `gateways.json`）。

### 5.2 手动分步构建（理解原理 / 排查问题时用）

```powershell
npx vite build                              # ① 生成 dist/ 前端资源
cargo build --release -p simuxchange       # ② 编译 Rust 主程序（嵌入 dist）
```

⚠️ **关键注意点（曾导致发布版白屏）**：
`src-tauri/Cargo.toml` 中必须保留以下配置——

```toml
[features]
default = ["custom-protocol"]
custom-protocol = ["tauri/custom-protocol"]
```

`custom-protocol` 特性的作用是**把 dist 前端资源嵌进 exe**。若缺少
`default = ["custom-protocol"]`，`cargo build --release` 出来的 exe
会去加载开发地址 `http://127.0.0.1:14200`，表现为启动后**「localhost 拒绝连接」**。
（dev 模式不受影响：Tauri CLI 以 `--no-default-features` 运行并加载 devUrl。）

### 5.3 发布版部署文件布局

```
任意目录/
├─ simuxchange.exe      # 主程序
├─ simx.config.json     # 运行配置（local/remote + 可选 updateUrl + llm），与 exe 同目录
├─ Linux/               # 构建产物自带的 Linux 后端（musl 静态编译，拷到服务器即可用）
│   ├─ simx-server
│   ├─ start.sh         # crontab 定时启停脚本（见 6.3 节）
│   └─ stop.sh
├─ gateways.json     # 网关配置（程序自动生成/维护）
├─ packets/          # 收发报文日志（平台开启“展示收发报文”时自动生成）
│   └─ 20260814/                # 按日期分文件夹（YYYYMMDD）
│       └─ 分组7深圳模拟撮合1_现货集中竞价交易平台/   # 日期下按“网关名_平台名”分文件夹
│           └─ pkg_203526_ip-192_168_1_100_port-8080.log   # 每条连接一个文件
└─ log/              # 前端操作日志（带前端 IP，自动生成）
    └─ 20260816/                # 按日期分文件夹（YYYYMMDD）
        └─ ops.log              # 当天全部操作日志
```

文件名格式：`pkg_<接入时分秒>_ip-<客户端IP点转下划线>_port-<客户端端口>.log`（
连接号不体现在文件名里，对端 IP:端口与接入时间即可唯一定位一条连接；
断开后文件保留，重连产生的报文写进新文件）。

报文文件内容与界面弹窗展示一致，每条报文两行：
`时:分:秒.毫秒 RECV/SEND  大写十六进制字节`（RECV=收，SEND=发）下方紧跟
按交易所字段名解析的缩进续行（`字段名: 值`），逐行 flush 写入。

程序按「exe 同目录 → 开发目录（target/debug 上溯）」的顺序查找数据目录，
所以**部署时把 `simx.config.json` 和 exe 放在一起**即可。

## 6. 构建独立后端 simx-server（远程部署）

### 6.1 构建

Windows 本机构建：

```powershell
cargo build --release -p simx-server
```

命令行控制工具 `simx-cli`（没界面，给自动测试脚本用，详见《产品使用手册》第 8 章）
同法构建，产物 `target\release\simx-cli.exe`；Linux 交叉编译时由
`build-all.ps1` 一并产出（simx-server / simx-update-server / simx-cli 三个一起编，
Windows 版 CLI 也由该脚本顺带编出）：

```powershell
cargo build --release -p simx-cli
```

**一键打包**：`.\scripts\pack-all.ps1` 一条命令跑完 `npm run tauri build -- --no-bundle`
（beforeBuildCommand 即 build-all.ps1：Linux 三件套 + Windows CLI + 前端 + 桌面端），
按固定布局汇总到 `dist\pkg\SimuXchange\` 并压缩为 `dist\SimuXchange_V<版本号>.7z`
（`dist\` 已在 .gitignore）。**不再生成 NSIS 安装包**；若只需桌面 exe，直接
`npm run tauri build`（同样只出 exe）。

产物 `target\release\simx-server.exe`，临时运行：

```powershell
.\simx-server.exe --listen 0.0.0.0:9800
```

- `--listen`：WebSocket 控制接口监听地址（前端连 `ws://IP:9800/ws`）
- **数据目录**：固定为程序（exe）所在目录，网关配置与启停状态（`gateways.json`，
  每个网关的 `wasRunning` 字段记录“上次是否在运行”）、报文文件 `packets/`、
  前端操作日志 `log/` 都在这里（与桌面端“配置放 exe 旁边”的约定一致），整个目录拷走即可迁移；
  开发模式下 exe 在 `target/debug/`，数据会落在那里（正常现象）
- `--auto-start`：**可选**。启动完成后自动恢复**上次运行中**的网关（引擎把网关启停
  状态记在 `gateways.json` 的 `wasRunning` 字段，只启动上次退出时仍在运行的网关）；
  不加则保持原有行为，所有网关都不自动启动，由界面手动启动
- `-V` / `--version`：**可选**。打印版本号（如 `simx-server 2.0.0`）后立即退出，
  不启动服务；正常启动时横幅也会打印版本（`SimuXchange 后端已启动 v2.0.0`），
  部署后从启动日志即可确认运行版本

### 6.2 Linux 部署（推荐：用户目录 + crontab 定时启停）

simx-server 提供两个版本：

- `simx-server-musl`：**默认**。musl 静态链接，不依赖任何系统库，任意 x86_64 Linux
  发行版可直接运行，无需在服务器安装 Rust/编译环境；
- `simx-server-glibc`：**需要 Oracle 查询（同步持仓数据）时用**。动态链接，要求
  目标机 glibc ≥ 2.17，配合 `start.sh` 把 Instant Client 目录加入 `LD_LIBRARY_PATH`。

部署在**用户目录**下，无需 root：

**① 获取程序**——从发布包 `Linux\simx-server\` 拷贝（两个版本都拷过去，后续切换方便）：

```bash
# 1. 上传到服务器并安装到用户目录：~/simx-server/
#    在解压后的发布包根目录执行；脚本和可执行文件必须同目录
mkdir -p ~/simx-server
cp Linux/simx-server/simx-server-musl Linux/simx-server/simx-server-glibc \
   Linux/simx-server/start.sh Linux/simx-server/stop.sh ~/simx-server/
chmod +x ~/simx-server/simx-server-musl ~/simx-server/simx-server-glibc \
         ~/simx-server/start.sh ~/simx-server/stop.sh
```

> 数据目录 = **程序所在目录**（即 `~/simx-server/`）：网关配置与启停状态
> （`gateways.json` 的 `wasRunning` 字段）、报文文件 `packets/`、日志都在
> 这一个目录下，无需另行准备数据目录。

> **怎么选版本**：只做网关模拟、不用 Oracle → 用 `simx-server-musl`（默认，省心）；
> 要在 Linux 服务端点「同步持仓数据」→ 用 `simx-server-glibc`（并确保 glibc ≥ 2.17）。
> 两个版本的 `--listen` / `--auto-start` 参数完全一样。

```bash
# 后台启动（推荐）
~/simx-server/start.sh            # 默认 musl 版
~/simx-server/start.sh glibc      # 需要 Oracle 查询时用 glibc 版

# 手动前景试运行（Ctrl+C 退出）；加 --auto-start 可启动后自动恢复上次运行中的网关
~/simx-server/simx-server-musl --listen 0.0.0.0:9800 [--auto-start]
~/simx-server/simx-server-glibc --listen 0.0.0.0:9800 [--auto-start]
```

### 6.3 crontab 定时启停（推荐）

用 `start.sh` 与 `stop.sh`（随发布包 `Linux\simx-server\` 目录一起提供）配进当前用户的 crontab，
**每天定时启动/停止后端**（如早 8 点开、晚 10 点关），无需 root、
无需 systemd。盘中进程异常退出不会自动拉起（本方案不做保活）：

```bash
# 1. 脚本已在 ~/simx-server/（与两个 simx-server 程序同目录）并已加执行权限（见 6.2 ①）
# 2. 编辑当前用户的定时任务（把 user 换成实际用户名）
crontab -e
# 加入下面两行后保存（每天 08:00 启动、22:00 停止）：
0 8 * * *  /home/user/simx-server/start.sh
0 22 * * * /home/user/simx-server/stop.sh

# 需要 Oracle 查询时，把启动行改为带 glibc 参数：
# 0 8 * * *  /home/user/simx-server/start.sh glibc

# 3. 确认已生效
crontab -l
```

也可手动执行 `~/simx-server/start.sh` / `~/simx-server/stop.sh` 随时启停
（glibc 版用 `start.sh glibc`；start.sh 已在运行时直接跳过，不会重复启动导致端口冲突；
stop.sh 会停掉 musl/glibc 任意一个正在运行的版本，并顺带清理 `log/` 与 `packets/` 下
**7 天前**按日期归档的文件夹，长期运行不会堆积旧日志）。

常用运维命令：

```bash
tail -f ~/simx-server/server.log   # 实时滚动后端日志
```

若启用了防火墙（ufw）：`sudo ufw allow 9800/tcp`。

> 说明：start/stop 脚本与 systemd 是两种实现同样目的的方式——
> systemd 需要 root 且随系统服务管理；crontab 定时启停完全在用户目录下，
> 适合无 root 权限的个人服务器。

### 6.4 前端切换远程后端

桌面端右上角徽章（本地引擎/远程后端）**本身就是切换入口**：点击后可在弹窗里
**配置多个后端**（本地引擎为固定项，远程可添加/删除多个），点选即切换，
立即生效并写入 `simx.config.json`（下次启动自动生效），无需手改配置文件。
等效的手工配置方式：

```json
{
    "backend": "b-srv1",
    "remoteUrl": "ws://<服务器IP>:9800/ws",
    "backends": [
        { "id": "local", "name": "本地引擎", "kind": "local", "url": "" },
        { "id": "b-srv1", "name": "测试机房", "kind": "remote", "url": "ws://<服务器IP>:9800/ws" }
    ]
}
```

`backend` 字段存当前选中的后端 id；旧版配置文件（只有 backend/remoteUrl）
仍可正常使用，程序会自动把“远程”合成为一个列表项。

### 6.5 部署后验证

1. 服务器上执行 `~/simx-server/start.sh`，`pgrep -f "simx-server --listen"` 能查到进程
2. 本机浏览器访问 `http://<服务器IP>:9800/health` 返回 `ok`
3. 桌面端点击右上角徽章，在弹窗里添加远程后端填地址，点选后右上角显示
   「<名称>·已连接」即成功；断线后界面每 2 秒自动重连

### 6.6 搭建更新服务器（自动升级）

升级采用**目录发布**：服务器上放"整个程序目录 + 一个版本号文件"，客户端把整个
目录下载下来原地覆盖。升级程序会自动扫描目录、生成文件清单，用户不用手写。

**用项目自带的 `simx-update-server`**，构建：

```powershell
cargo build --release -p simx-update-server                           # Windows
cargo build --release -p simx-update-server --target x86_64-unknown-linux-musl   # Linux（musl 静态，可拷贝到任何发行版）
```

部署运行（Linux 服务器为例；发布包 `Linux\simx-update-server\` 里已包含程序与启停脚本）：

```bash
mkdir -p ~/simx-update
cp Linux/simx-update-server/* ~/simx-update/   # 在解压后的发布包根目录执行
cd ~/simx-update
./simx-update-server --listen 0.0.0.0:9860
```

目录布局（版本文件与程序同级，发布目录名 = 版本号）：

```
~/simx-update/
├─ simx-update-server
├─ release.txt      ← 内容仅一行版本号，如 2.1.0
└─ 2.1.0/           ← 整个发布目录（simuxchange.exe 与其它文件/子目录）
```

服务器每次请求按 `release.txt` 解析同名目录，换版本只需改 `release.txt` 并放好
对应目录，无需重启。查看升级服务器自身版本：`./simx-update-server --version`
（与 release.txt 里的"发布版本号"是两回事——后者是待发布的客户端版本）。

发布新版步骤（唯一要做的两件事）：

1. 把**压缩包解压后的整个程序目录**（simuxchange.exe 与其它文件/子目录）拷进
   与版本号同名的目录（如 `2.1.0/`，覆盖或追加文件即可）；
2. 更新**程序同目录**的 `release.txt`：纯文本，内容仅一行版本号，如 `2.1.0`。

服务器自动递归扫描版本目录（含子目录），为每个发布文件计算 size/sha256 生成
`version.json`，并通过 `/update/<相对路径>` 提供下载；已有旧版本的文件不会被自动
删除（目录里旧文件可手动清理，`/api/files` 列出文件、`/api/file/<名>` 删除）。
浏览器打开 http://<服务器IP>:9860 即管理页（当前清单 + 文件列表 + 删除）。

**后台运行与日志**（发布包 `Linux\simx-update-server\` 内含 `start-update.sh` / `stop-update.sh`）：

```bash
# 程序与脚本已按上面一起拷到 ~/simx-update/
chmod +x ~/simx-update/simx-update-server ~/simx-update/start-update.sh ~/simx-update/stop-update.sh
~/simx-update/start-update.sh    # nohup 后台启动；已在运行则跳过（可配 crontab）
tail -f ~/simx-update/update-server.log
~/simx-update/stop-update.sh     # 先 TERM 优雅退出，10 秒未退再 KILL
```

脚本按自身所在目录定位程序和 `release.txt`，固定 `--listen 0.0.0.0:9860`，
输出追加写入同目录 `update-server.log`（停止时保留）。二进制本身保持前台运行，
由脚本负责后台化，systemd/docker 等方式也可直接托管该进程。

桌面端「更新服务器地址」填 `http://<服务器IP>:9860/update`；启动 3 秒后拉
`version.json`，发现新版后**自动在后台下载**（不弹窗，顶栏关于按钮显示
「⇣ 下载中」）；下载完成（主 exe 最后、逐文件 sha256 校验）后顶栏变红
「↻ 重启以更新」，点击覆盖并重启，关闭则下次启动生效。
主 exe 名字匹配 `simuxchange.exe`（见 `src-tauri/src/updater.rs`）。

**实现要点（维护用）**：版本号只在 `release.txt` 里；`version.json`
由 `build_manifest` 实时扫描目录生成（无 release.txt 或无文件时返回 404，客户端静默）；
下载路由为 axum 0.7 通配 `/update/*`（支持子目录，`..` 路径穿越拒绝）；
`release.txt` 在发布目录之外，不会出现在清单、也不会被下载；
版本比较"数字点分"（1.10.0 > 1.9.0）。

`version` 用"数字点分"比较（如 1.1.0 > 1.0.9）；发布新版本时同步更新
`tauri.conf.json` 与 `package.json` 以及 `src/changelog.ts`
（界面"ⓘ 关于"里的更新说明）。

## 8. 踩坑记录（重要！）

### ① Vite 启动报 `listen EACCES: permission denied 127.0.0.1:1420`

**不是权限问题。** Windows 将 1381–1480 端口段保留给 Hyper-V/WSL，查看保留段：

```powershell
netsh interface ipv4 show excludedportrange protocol=tcp
```

Vite 默认端口 1420 恰好落在保留段内。本项目已改用 **14200**；
若再遇到，选保留段之外的端口，并**同步修改两处**：
`vite.config.ts` 的 `server.port` 和 `tauri.conf.json` 的 `devUrl`。

### ② 发布版 exe 启动显示「localhost 拒绝连接」/ 白屏

`custom-protocol` 特性未启用，前端资源没有嵌入 exe。确认
`src-tauri/Cargo.toml` 的 `[features]` 下有 `default = ["custom-protocol"]`
（见 5.2 节），然后重新 `cargo build --release -p simuxchange`。

### ③ 新终端找不到 `cargo` 命令

rustup 安装器已写入 PATH，但只对**之后新开的终端**生效。重开终端，或临时执行：

```powershell
$env:Path = "$env:USERPROFILE\.cargo\bin;$env:Path"
```

### ④ cargo 编译报「拒绝访问 (os error 5)」

多发生在 `build-script-build` 阶段，是杀毒软件/系统对临时生成的构建脚本
exe 的拦截，**并非代码问题**。重跑一次构建命令通常即可通过；
反复出现时把项目目录和 `target\` 加入杀毒软件白名单。
另外**避免 `cargo check --workspace` / `cargo build --workspace` 这类全量命令**——
任一包的构建脚本被拦截都会拖垮整体，按包分开检查（`-p`）更稳也更快
（日常用 `cargo check -p simx-core -p simx-server` 足够）。

### ⑤ PowerShell 里命令连不起来

老版本 PowerShell 不支持 `&&`，用分号：

```powershell
npx vite build; cargo build --release -p simuxchange
```

### ⑥ cargo 显示 ExitCode 1 但其实编译成功

PowerShell 把 cargo 的进度条输出当 stderr 处理，某些终端封装据此误判失败。
**以输出末尾的 `Finished`（编译）/ `test result: ok`（测试）为准。**

### ⑦ 修改了后端 Rust 结构体，前端类型报错

前后端类型是手工对应的：Rust 结构体（serde 序列化为 camelCase）↔
`src/types.ts` 的 interface。改任何一边都要**同步改另一边**。

### ⑧（已废弃）打包时报 NSIS 下载超时

打包已改为 `pack-all.ps1` + 7z（`tauri build --no-bundle`、`bundle.active=false`），
不再调用 NSIS，本条不再适用。

### ⑨ cargo 拉取依赖报 `spurious network error ... 404`

本机全局 `~/.cargo/config.toml` 默认走 tuna（git 镜像），网络波动时经常 404。
解决办法：在**项目根建 `.cargo/config.toml`** 覆盖为 aliyun sparse 镜像
（文件方式最可靠，命令行 `--config` 在 PowerShell 里引号易被吃掉）：

```toml
[source.crates-io]
registry = "https://github.com/rust-lang/crates.io-index"
replace-with = "aliyun"

[source.aliyun]
registry = "sparse+https://mirrors.aliyun.com/crates.io-index/"

[http]
check-revoke = false
```

删除该文件即恢复全局配置。aliyun 连通性自查：
`curl.exe -s -o NUL -w "%{http_code}" https://mirrors.aliyun.com/crates.io-index/config.json`
返回 200 即正常（注意 PowerShell 里 `curl` 是 Invoke-WebRequest 别名，要用 `curl.exe`）。

### ⑩ PowerShell 脚本中文变乱码、报“字符串缺少终止符”

Windows PowerShell 5.1 对 **UTF-8 无 BOM** 的 .ps1 按 ANSI（GBK）读取，
中文注释/字符串会乱码并引发解析错误。**新建含中文的 .ps1 必须保存为 UTF-8 with BOM**
（编辑器的“带 BOM 的 UTF-8”；或转换：
`$c = Get-Content -Raw -Encoding UTF8 a.ps1; [IO.File]::WriteAllText((Resolve-Path a.ps1), $c, (New-Object Text.UTF8Encoding $true))`）。
`scripts/build-all.ps1` 由 tauri 的 beforeBuildCommand 调用，踩过此坑。

### ⑪ 项目目录搬迁后报 "failed to read plugin permissions ... 系统找不到指定的路径"

`target\` 里的构建脚本缓存（如 `tauri-*` 的 `out\permissions\`）会**内嵌生成时的
项目绝对路径**，而 cargo 的指纹不记录工作目录位置——项目目录改名/搬家后这些
缓存不会自动失效，打包时 tauri 构建脚本去读旧路径下的文件直接报错。
解决办法：删除对应 profile 的构建脚本缓存目录（musl 产物在独立目录
`target\x86_64-unknown-linux-musl\`，不受影响）：

```powershell
Remove-Item -Recurse -Force target\release\build, target\debug\build
```

之后正常重跑 `npm run tauri build`（依赖会重新编译一遍，一次性代价）。

### ⑫ 为 musl 设置的全局 RUSTFLAGS 炸掉 Windows 侧编译（-C link-self-contained is not supported on this target）

`build-all.ps1` 里为 musl 交叉链接设置 `RUSTFLAGS=-C linker=rust-lld -C
link-self-contained=yes` 是**全局环境变量**：带 `--target` 编 musl 时它只作用于
musl target（host 侧 build script 不受影响，所以历史上一直没暴露）；但脚本随后
编译 Windows 版 `simx-cli` 时**不带 `--target`**（host 即 MSVC），RUSTFLAGS 会
作用于包括 build script / proc-macro 在内的所有编译单元，而
`-C link-self-contained` 是 musl/linux-gnu 专属选项，MSVC 直接报
`option '-C link-self-contained' is not supported on this target`；只要
Cargo.lock 变化触发 host build script 重编就会复现（2026-09 加入 simx-cli
新依赖时引爆）。

**修复**：musl 链接参数改用 target 专属变量
`CARGO_TARGET_X86_64_UNKNOWN_LINUX_MUSL_RUSTFLAGS`（只作用于 musl target，
host 编译不受影响），并在脚本开头 `Remove-Item Env:RUSTFLAGS` 防外部污染。
注意：全局 `RUSTFLAGS` 非空时 cargo 会**忽略** target 专属变量，二者不能共存。
